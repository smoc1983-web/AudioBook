AudioBook 4.0 — исправления прокрутки и возврата из фона

Установка
1. Замените app/src/main/java/com/MainActivity.kt файлом MainActivity.kt из архива.
   Сохраните расположение файла в вашем проекте; package остаётся com.audiobookdownloader.
2. Запустите :app:assembleDebug в Code On The Go.
3. Установите полученный APK поверх текущей версии приложения, сохранив его данные.
   PlaybackService.kt и AudioBookWidget.kt для этого обновления заменять не требуется.

Что изменено
- Скрытые браузеры главных каталогов вынесены из LazyColumn. Прокрутка теперь
  управляет только карточками, а не создаёт и уничтожает браузеры сайтов.
- Главные каталоги загружаются последовательно, результаты сохраняются в состоянии экрана.
- Освобождение WebView выполняется один раз после отсоединения AndroidView от окна.
  Ручное удаление дочерних View из контейнеров Compose исключено.
- При onStop задачи браузеров отменяются синхронно, даже если Compose уже приостановлен.
  При onStart создаётся новое поколение браузеров для незавершённых запросов.
  Каждый Activity закрывает только собственные браузеры.
- Все клиенты WebView обрабатывают потерю процесса рендеринга; запрос завершается
  сообщением о возможности повторить его. Внешний классификатор не запускает JS
  на браузере, потерявшем процесс. Родитель и вложенный поиск освобождают общий WebView один раз.
- Фоны темы и галереи декодируются в фоне с ограничением размера 1280 пикселей
  по большей стороне. Верхний блок поиска и фон приложения используют общий кэш.
- При сигнале о нехватке памяти освобождается кэш изображений; отображаемые Bitmap
  не recycle-ятся. Чтение длительностей остаётся на IO, обновление состояния Compose — на Main.
- Добавлен локальный отчёт о необработанной Java/Kotlin-ошибке. На Android 11+ также
  читаются сведения Android о последнем сбое, ANR, ошибке запуска и нехватке памяти.
  Сохраняется стандартный обработчик ошибок Android/Code On The Go.

Как получить отчёт без Logcat
После повторного сбоя снова откройте приложение. Новый доступный отчёт откроется
автоматически. Или нажмите шестерёнку → «Диагностика» → «Отчёт о последнем сбое».
Нажмите «Скопировать отчёт» и вставьте текст в сообщение. «Поделиться отчётом»
открывает системный выбор приложения. Автоматической отправки нет.
На Android ниже 11 нативные ошибки, ANR и системное завершение процесса могут
не записываться этим механизмом. Системный отчёт о нехватке памяти содержит причину
завершения, но не обязательно стек ошибки. До установки этого обновления локальный
обработчик Java/Kotlin не был установлен, поэтому прежний стек не восстановить.

Проверка на телефоне
После сборки проверьте многократную прокрутку главной страницы поиска вверх и вниз,
переходы между вкладками и возвращение после блокировки экрана. Отдельно проверьте
возобновление незавершённого поиска и продолжающееся воспроизведение в сервисе.
Если вылет повторится, пришлите отчёт и укажите действия перед ним.

Что проверено здесь
Проверка скобок и строк Kotlin, сохранение opt-in для ExperimentalComposeUiApi,
отсутствие изменений PlaybackService.kt и 28 сценариев actual JavaScript-парсеров
каталога, циклов и внешнего классификатора на подготовленных HTML/JSON.
Эти проверки не заменяют компиляцию или запуск Android.
Полного Gradle-проекта, Android SDK и устройства в рабочей среде нет.
assembleDebug не запускался. Архив содержит исходник, а не готовый APK.
Причина именно присланного сбоя без стека/системного отчёта не подтверждена;
исправлены обнаруженные в коде проблемы жизненного цикла и расхода памяти.

Необязательный файл audiobook-4.0.init.gradle сохранён из предыдущего обновления
для установки versionName 4.0, если это ещё не указано в Gradle вашего проекта.
Он не нужен для самого исправления сбоя.
