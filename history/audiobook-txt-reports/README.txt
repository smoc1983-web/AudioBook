Audiobook — отправка диагностики файлом TXT
Ревизия: 4.0-txt-report-1
Архив содержит исходники, не готовый APK.
Основа — последняя объединённая версия с анимацией запуска.

КАК ПОЛЬЗОВАТЬСЯ

Настройки → Диагностика → Диагностика и логи → Отправить отчёт (.txt).

Приложение создаёт текстовый файл UTF-8 и открывает стандартное меню
Android для выбора получателя: Telegram, почты или другого приложения.
Передаётся вложение .txt, а не длинное сообщение с текстом отчёта.
Получателя и окончательную отправку выбираете вы.

Кнопки «Скопировать отчёт» и «Отправить текстом» сохранены.
Диагностика не появляется при запуске и сама никуда не отправляется.

ЧТО РЕАЛИЗОВАНО

— В файл записывается именно уже собранный отчёт из открытого окна,
  включая сведения о сборке, проверке источника, событиях плеера
  и сбое Android, если они есть. Во время экспорта отчёт не пересобирается.
— Файл UTF-8 имеет уникальное имя Audiobook-report-ДАТА-ВРЕМЯ-суффикс.txt.
— Запись выполняется в фоне. Пока файл готовится, отображается состояние
  подготовки и блокируется повторная отправка. Есть сообщения об ошибках.
— Закрытие диагностики отменяет подготовку; завершение старой операции
  не должно открывать отправку для уже закрытого/заменённого отчёта.
— Файл хранится в отдельной папке внутреннего кэша diagnostic-reports.
  Получателю передаётся content URI с временным разрешением только на чтение.
  Весь кэш, скачанные книги и прочие файлы ему не открываются.
— При следующем экспорте удаляются только собственные отчёты старше суток.
  Только что отправленный файл сразу не удаляется, чтобы получатель
  успел прочитать вложение. Кэш также может очищаться самой системой.
— Новых разрешений на доступ к общей памяти не требуется.

УСТАНОВКА ДЛЯ DEBUG / CODE ON THE GO

Сделайте резервные копии перед заменой. Для этой функции необходимы
ТРИ файла; переносите их вместе по указанным путям:

1. MainActivity.kt → app/src/main/java/com/MainActivity.kt
2. app/src/debug/AndroidManifest.xml → тот же путь в проекте
3. app/src/main/res/xml/audiobook_diagnostic_paths.xml → тот же путь в проекте

Папку res/xml создайте, если её нет. Папка debug расположена рядом
с main, а не внутри неё. Не удаляйте другие файлы проекта.

Второй файл — прежний debug-манифест с добавленным provider для отчётов;
сервис воспроизведения, разрешения и отключение LogSender сохранены.
Если ваш debug-манифест содержит собственные дополнительные настройки,
добавьте в него новый блок provider, сохранив свои изменения.

Соберите :app:assembleDebug, установите APK и проверьте ревизию
4.0-txt-report-1 в диагностике. Данные и книги очищать не требуется.

ДЛЯ RELEASE

В архив включён app/src/release/AndroidManifest.xml с тем же provider.
Если такого файла в проекте нет, перенесите его по указанному пути.
Если release-манифест уже существует, добавьте блок provider внутрь
существующего application, сохранив остальные записи. Для других
вариантов сборки этот блок можно добавить в основной манифест
app/src/main/AndroidManifest.xml вместо отдельных overlay-манифестов.
Сам основной манифест в архиве не заменяется.

Блок provider:

<provider
    android:name="com.audiobookdownloader.AbDiagnosticReportProvider"
    android:authorities="${applicationId}.diagnostic_reports"
    android:exported="false"
    android:grantUriPermissions="true">
    <meta-data
        android:name="android.support.FILE_PROVIDER_PATHS"
        android:resource="@xml/audiobook_diagnostic_paths" />
</provider>

Класс AbDiagnosticReportProvider находится в MainActivity.kt.
FileProvider входит в AndroidX Core, используемый AndroidX Activity
и текущим приложением; отдельных новых зависимостей не добавлено.

ПРОВЕРКА НА ТЕЛЕФОНЕ

1. Откройте диагностику и нажмите «Отправить отчёт (.txt)».
2. Выберите Telegram/почту и проверьте, что прикреплён именно .txt-файл.
3. Откройте его: русский текст должен читаться корректно, а содержимое
   должно совпадать с отчётом в диагностике, включая ревизию и время.
4. Отмените выбор получателя и повторите отправку. Новая попытка должна
   создавать отдельный файл. Проверьте также копирование и отправку текстом.

ПРОВЕРЕНО И ОГРАНИЧЕНИЯ

Проверена структура Kotlin/XML и согласованность класса provider,
уникального authority и ресурса путей в debug и release. Проверено,
что путь ограничен одной папкой кэша, передаётся content URI с правом
чтения, а старые компоненты и разрешения debug-манифеста сохранены.
Прошли 14 структурных/регрессионных проверок исходников.

Анимация запуска, все извлечённые JavaScript-обработчики источников,
PlaybackService.kt и SearchBookIndex.java побайтно совпадают с предыдущей
объединённой версией. Парсеры не менялись, их тестовые сценарии повторно
не запускались.

Это не компиляция Kotlin и не проверка Android FileProvider на устройстве.
Полного Gradle-проекта и Android SDK здесь нет: APK не собирался,
объединение манифестов Android Gradle Plugin и реальная отправка вложения
в Telegram/почту должны быть проверены после сборки на телефоне.
