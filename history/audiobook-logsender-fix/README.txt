AudioBook 4.0 — LogSender и AndroidView
Ревизия: 4.0-logsender-interop-1

Разбор отчёта
- Событие 12 октября: Android завершил процесс по нехватке памяти.
  RSS около 64 МБ само по себе не устанавливает утечку памяти в приложении.
- Стек 10 октября: LogSenderInstaller редактора AndroidIDE/Code On The Go
  вызывает LogSenderService, а Android запрещает запуск foreground-сервиса
  в данном состоянии процесса. Это происходит до MainActivity.
- Отдельные стеки 10 октября: NullPointerException в AndroidViewHolder при
  измерении Android View внутри Compose.
  Эти записи исторические и не доказывают новый сбой установленной версии.

Что установить — нужны ДВА файла
1. Замените MainActivity.kt по его существующему пути:
   app/src/main/java/com/MainActivity.kt
2. Добавьте файл из архива по точному пути:
   app/src/debug/AndroidManifest.xml
   Если каталог debug отсутствует, создайте его.

ВАЖНО: это дополнительный манифест для debug-сборки.
Он не предназначен для замены app/src/main/AndroidManifest.xml.
Если app/src/debug/AndroidManifest.xml уже существует, сохраните его содержимое,
добавьте xmlns:tools="http://schemas.android.com/tools" в корневой manifest и
перенесите из приложенного файла два элемента provider/service в application.
Не создавайте второй application и не добавляйте одинаковые элементы повторно.

Затем выполните :app:assembleDebug и установите обновление поверх приложения.
Удалять приложение и очищать библиотеку не требуется.
PlaybackService.kt и AudioBookWidget.kt не изменены.

Почему дополнительный манифест необходим
LogSenderInstaller создаётся системой до запуска MainActivity. Код экрана
не может перехватить исключение этого ContentProvider.
Маркер tools:node="remove" исключает из объединённого debug-манифеста только
два компонента LogSender. Сервис воспроизведения AudioBook остаётся в проекте.
Передача текущих логов в окно App Logs редактора через LogSender будет отключена.
Встроенный отчёт приложения и чтение журнала собственного UID сохранены.
Строка «Add LogSender dependency» при сборке может остаться: отключены его
компоненты в манифесте, а не сам Gradle-плагин/библиотека.

Правка интерфейса
Все AndroidView удалены из MainActivity:
- Скрытые WebView создаются как отдельные сеансы без добавления в Compose.
  Им задаются размеры, сохраняются JavaScript/загрузка страниц/разбор DOM.
  При уходе с экрана или остановке Activity сеанс закрывается.
- Компоненты обложек рисуют Bitmap напрямую через Compose Image.
- Фоновые кандидаты жанров проверяются по одному вместо двух одновременно.
  Это ограничивает число параллельных браузеров; поиск может занимать дольше.
- Прямой поиск Азбуки, категории, циклы, сохранённая библиотека, настройки,
  плеер и предыдущая защита запуска остаются.

Проверка на телефоне
При первом запуске этой ревизии появится экран восстановления.
Нажмите «Обычный запуск» и проверьте:
- повторное открытие после сворачивания;
- вертикальную прокрутку поиска и библиотеки;
- поиск «Лествица»/открытие каталога Азбуки;
- воспроизведение с выключенным экраном.
Для проверки освободите память от редактора/сборки после установки.
Если будет новый вылет, скопируйте отчёт через экран восстановления.
Даты старых записей в журнале сами по себе не означают повторение ошибки.

Проверки пакета
XML проверен на корректность и точность удаляемых компонентов.
Пройдены проверки Kotlin-скобок/строк, жизненного цикла сеансов и прежнего ANR.
Прошли 50 прежних сценариев разбора данных на искусственных DOM-примерах.
Скрипты сайтов и PlaybackService.kt побайтно совпадают с предыдущей версией.

Полного Gradle-проекта и Android SDK в рабочей среде нет.
assembleDebug, реальное объединение манифестов, сетевые сеансы WebView без
Compose и работа на Samsung здесь не проверялись. Системное завершение по
дефициту памяти требует отдельного наблюдения; эта правка не подтверждает
устранение всех таких завершений.
