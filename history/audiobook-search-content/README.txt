Audiobook — исправление поиска, карточек без глав и ANR жанров
Диагностическая ревизия: 4.0-search-content-anr-1

ОСНОВНЫЕ ИСПРАВЛЕНИЯ

1. Зависание жанровой выдачи (ANR).
В отчёте Samsung от 18.10.2026 главный поток остановился в цепочке
updateGenreResults → mergeSearchBooks → searchBookIdentity → Regex.
Прежний код перебирал уже найденные книги для каждой новой записи и
многократно компилировал одинаковые регулярные выражения.

Теперь используется индекс URL, названий, авторов и источников.
Регулярные выражения нормализации создаются один раз. Разные тома и книги
с явно разными авторами сохраняются отдельно. Поддерживаются е/ё,
римские номера томов и разный порядок имени/фамилии автора.
Объединение жанровой и обычной выдачи выполняется на Dispatchers.Default.
Устаревшая работа отменяется; ответы предыдущего поиска не подменяют
новый экран. Чтение сохранённых метаданных вынесено на IO.

Показываются порции по 60 книг: «Показать ещё» раскрывает уже полученную
выдачу без нового запроса. Загрузка новых страниц источников запускается
отдельной кнопкой. В одном поиске хранится до 600 результатов, после
чего приложение предлагает уточнить название или автора.
Это предохранитель объёма выдачи, а не удаление книг с устройства.
Возврат из карточки восстанавливает выдачу, жанр и место прокрутки,
включая ранее раскрытые порции.

2. Ссылка жанра больше не становится отдельной книгой.
Снимок с позицией «Ужасы, мистика, хоррор» и обложкой второго тома
воспроизведён как отдельный пример парсера. Теперь ссылки автора,
жанра, чтеца и цикла проверяются по их роли внутри карточки.
Ссылка на обложке связывает её с правильным адресом книги.
Настоящие произведения с названием вроде «Фантастика» не отбрасываются
только из-за совпадения названия со словом жанра.
Обычный поиск дополнительно проверяет соответствие слов запроса
названию, автору или серии. Жанровая принадлежность определяется
метаданными, а не словами в названии.
Старые кешированные жанровые записи используются как кандидаты для
внешней проверки, без автоматического признания их доступными книгами.
Коллекции, закладки и сохранённые пользователем материалы не удаляются.

3. Более устойчивое чтение глав.
Парсер плеера Книгоблуда поддерживает пробелы в KB.playerInit, комментарии,
одинарные кавычки, ключи без кавычек, завершающие запятые и JSON.parse.
Также обрабатываются явные JSON-блоки плеера, data-playlist и audio/source.
Строки с кодом не исполняются. Неподдерживаемые и неверные записи
пропускаются; относительные аудиоссылки приводятся к абсолютным.
На странице книги рекомендации не подменяют отсутствующий список глав.
Для динамической страницы увеличено ожидание появления плейлиста;
сохранены общий тайм-аут, отмена запросов и проверка сертификата сайта.

4. Вместо пустого экрана — карточка состояния.
Во время открытия сразу видны выбранное название, обложка, источник
и индикатор. Если источник не отдаёт главы, остаются объяснение ошибки,
«Повторить открытие», адрес страницы, «Скопировать ссылку» и открытие
в обычном браузере. Можно вернуться к результатам поиска.
Если у этой же книги уже найдены альтернативные источники, приложение
последовательно пробует их. Используются только известные ссылки
из объединённой карточки, до трёх адресов, с ограничением времени.
Новые адреса, другие тома или названия для подмены не придумываются.
Одно неудачное открытие не удаляет книгу из коллекций и не означает,
что у источника вообще нет аудио. При необходимости точную ссылку
теперь можно скопировать прямо из карточки с ошибкой.

КАК УСТАНОВИТЬ

ВАЖНО: в этом исправлении добавлен ОБЯЗАТЕЛЬНЫЙ Java-файл.
Одной замены MainActivity.kt недостаточно.

1. Сохраните резервную копию текущих исходников.
2. Замените MainActivity.kt в app/src/main/java/com/MainActivity.kt.
3. Добавьте из архива файл ТОЧНО по пути:

   app/src/main/java/com/SearchBookIndex.java

   Его package уже задан: com.audiobookdownloader — как у MainActivity.kt.
   Скопируйте файл целиком, не вставляйте его содержимое в Kotlin-файл.
   Android Gradle Plugin автоматически подключает Java-исходники этого пути.
4. PlaybackService.kt приложен в прежней рабочей версии. Он побайтно
   совпадает с предыдущим архивом Audiobook-Search-Diagnostics.
   Если тот архив установлен, повторная замена сервиса не нужна.
5. Файлы названия и debug-манифест также сохранены без изменений:

   app/src/main/res/values/audiobook_branding.xml
   app/src/debug/AndroidManifest.xml

   Если уже установлены, их можно оставить. При обновлении с более старой
   версии перенесите их по этим точным путям, объединяя папки проекта.
   Не заменяйте целиком папку src. debug находится рядом с main.
6. Пересоберите :app:assembleDebug и установите полученный APK.
7. Проверьте «Настройки → Диагностика → Диагностика и логи»:
   должна быть ревизия 4.0-search-content-anr-1.

ПРОВЕРКА НА ТЕЛЕФОНЕ

— Повторить поиск «отель перекресток»: жанровая ссылка не должна быть
  отдельной книгой; тома сохраняются раздельно.
— Открыть жанр, прокрутить выдачу, раскрыть несколько порций и вернуться
  из карточки назад. При 600 книгах уточнить запрос в поле поиска.
— Проверить карточку с недоступными главами: название, ошибка, повтор,
  копирование URL и возврат к результатам должны оставаться доступны.
— Если проблема повторится, отправить отчёт новой ревизии и скопированную
  ссылку из карточки. В отчёте ANR важен блок главного потока main.

ДЛЯ RELEASE И ДРУГИХ ВАРИАНТОВ

Полного основного AndroidManifest.xml в полученных файлах нет; архив
не подменяет его. Для названия всех вариантов задайте android:label
существующего <application> и запускающей activity/activity-alias как
"@string/audiobook_product_name", если там есть собственная подпись.
Приложенный rename_launcher.py делает такую замену с резервными копиями.
Из корня проекта после копирования ресурса названия:

   python3 rename_launcher.py .

Это только просмотр. Для применения:

   python3 rename_launcher.py . --apply

Для обычной debug-сборки приложенный debug-манифест уже задаёт Audiobook.
