Синхронизация скачанных книг после обновления и переустановки

Замените MainActivity.kt и PlaybackService.kt. AudioBookWidget.kt менять не нужно.
Основа — последняя версия с общим поиском, просмотром циклов и свёрнутыми настройками.

Во вкладке «Книги» сверху добавлены:
- «СИНХРОНИЗИРОВАТЬ»: перечитать скачанные книги.
- «ВЫБРАТЬ ПАПКУ БИБЛИОТЕКИ»: системный выбор папки.
- «РАЗРЕШИТЬ ДОСТУП К АУДИО»: появляется, если разрешение не выдано.

После переустановки откройте «Книги». Если старые книги не появились,
выберите сохранённую папку Download/AudioBooks и предоставьте доступ.
Можно также выбрать папку отдельной книги. Папка AudioBooks должна содержать
папки книг, а в каждой папке — скачанные MP3. Сам корень Download на новых
версиях Android может быть запрещён для выбора; выбирайте подпапку AudioBooks.

Что изменено:
- Запрос аудиофайлов и уведомлений объединён: запросы больше не конфликтуют.
- Библиотека перечитывается после выдачи разрешения, возвращения в приложение,
  открытия «Книг», окончания загрузок и удаления книги.
- Сканирование выполняется в фоне. Список не зависит от сохранённых заданий
  DownloadManager, поэтому отсутствие записей старой установки не мешает поиску.
- Поиск использует папки Download/AudioBooks, системный каталог MediaStore
  и выбранную пользователем папку через Storage Access Framework.
- Доступ к выбранной папке сохраняется между запусками. После удаления приложения
  Android сбрасывает этот доступ; папку нужно выбрать заново.
- Главы из выбранной папки читаются через content URI без копирования MP3
  и повторного скачивания. Сервис использует эти адреса и для очереди.
- Сохраняется прежняя сортировка глав: первое число в названии, затем название.
- Для одинаковых путей книги/главы результаты разных способов сканирования
  объединяются. Пустые MP3 и недоступные записи MediaStore пропускаются.
- Обложка cover.jpg из выбранной папки отображается в библиотеке и плеере.
- Проверка скачанных глав на странице сайта учитывает найденные книги.

AndroidManifest.xml не предоставлен и не изменялся. Автоматический запрос доступа
к аудио требует соответствующих существующих uses-permission в манифесте:
    <uses-permission android:name="android.permission.READ_MEDIA_AUDIO" />
    <uses-permission android:name="android.permission.READ_EXTERNAL_STORAGE" android:maxSdkVersion="32" />
Выбор папки работает без этих двух разрешений, через отдельное системное согласие.

Восстанавливается список реально сохранившихся аудиофайлов. Удалённые файлы
и утраченные при удалении приложения настройки/прогресс сканирование не восстановит.

Проверка в этой среде:
- Проверены строки, комментарии и скобки обоих Kotlin-файлов.
- Проверены связи сканирования, запросов доступа и content URI плеера/очереди.
- Код общего поиска, циклов и блока настроек сохранён.
- Компиляция Kotlin/Compose, assembleDebug и запуск на Android не проверены:
  предоставлены отдельные исходники, полного Gradle-проекта и Android SDK нет.

Проверка на устройстве после сборки:
1. Существующие MP3 в Download/AudioBooks видны после выдачи доступа.
2. При запрете разрешения выбор AudioBooks показывает книги и даёт их воспроизвести.
3. После перезапуска выбранная папка остаётся подключённой.
4. При закрытом экране играет следующая глава и следующая скачанная книга из очереди.
5. Кнопка синхронизации обнаруживает добавленные главы и убирает удалённые книги.
