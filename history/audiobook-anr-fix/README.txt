AudioBook 4.0 — исправление зависания, редакция 4.0-anr-index-1

Замените MainActivity.kt в своём проекте и запустите :app:assembleDebug.
Установите APK поверх текущей версии, сохранив данные.
PlaybackService.kt и AudioBookWidget.kt менять не требуется.
Архив содержит исходник и инструкцию, готового APK нет.
За основу взят MainActivity.kt из AudioBook-4.0-azbyka.zip.

Причина из bag.txt
Отчёт Android 34, OnePlus CPH2399, 11 октября 2026, 13:27 GMT+04:
Input dispatching timed out — Android ожидал обработки касания 5000 мс.
Стек главного потока:
File.listFiles → isTrackDownloaded(MainActivity.kt:7133)
→ AudioBookApp$6$1.invokeSuspend(MainActivity.kt:2283).
Проверка скачанных глав перебирала папки AudioBooks на главном потоке.
Она повторялась для каждой главы каждые 1500 мс. Для отсутствующих файлов
проверка каждый раз переходила к обходу всех папок.
Тот же обход выполнялся при открытии книги и запросе загрузки.
На момент снимка главный поток ожидал внутри listFiles/NewStringUTF.
Отчёт подтверждает этот путь зависания; сам по себе он не доказывает
нехватку памяти и не исключает других причин зависаний.

Исправление
- isTrackDownloaded теперь выполняет только поиск в индексе памяти,
  без exists, length, listFiles, запросов MediaStore или обхода каталогов.
- Индекс строится вместе с фоновой синхронизацией библиотеки:
  обычные файлы, MediaStore и выбранная папка SAF учитываются как раньше.
- Обновление состояний глав реагирует на изменения книги/индекса,
  периодический цикл с интервалом 1500 мс удалён.
- Индекс содержит точные имена книги/папки и файлов. Книги с похожим
  началом названия не считаются одной и той же книгой.
- Запросы состояния DownloadManager при запуске и во время загрузки
  выполняются на Dispatchers.IO пакетами до 128 заданий.
  На главный поток возвращаются значения, а не открытые курсоры.
- Постановка загрузок, включая создание папки назначения Android,
  также выполняется на IO, одновременно не более двух запросов.
  Начинающаяся загрузка сразу видна; повторное нажатие не создаёт дубль.
- Запрос скачивания ожидает завершения текущей синхронизации, прежде
  чем определять, нужна ли загрузка главы.
- Отмена ожидающего запроса учитывается. Если Android уже создал задание,
  отмена пытается удалить его; при ошибке удаления остаётся запись
  для восстановления системного задания после перезапуска приложения.
- Несколько завершённых глав вызывают одну синхронизацию библиотеки.
  Фоновые сканирования сериализованы, частые обновления объединяются
  задержкой 250 мс.

Сохранено
Подключение Азбуки веры, общий поиск трёх источников, Саморазвитие,
M3U-плейлисты, обложки, серии, библиотека, плеер в сервисе и диагностика.
Исходные JavaScript-парсеры и PlaybackService.kt не изменены.

Проверка
Прошли статические проверки строк/скобок Kotlin, всех вызовов проверки
скачанности, отсутствия дискового fallback/таймера и размещения запросов
статуса/начала загрузки на IO. Проверены сохранение прежнего opt-in,
версии 4.0, реквизитов, неизменность сервиса и извлечённых парсеров.
Это не компиляция и не воспроизведение ANR на устройстве.
Полного Gradle-проекта, Android SDK и эмулятора здесь нет.
assembleDebug не запускался; APK не собран.

Проверка на телефоне
1. Откройте книгу с большим числом глав, часть которых не скачана.
   Прокрутите главы, перейдите в поиск и снова прокрутите страницу.
2. Заблокируйте телефон, затем вернитесь в приложение.
3. Запустите несколько загрузок, отмените одну и проверьте завершение.
4. Проверьте, что скачанные главы отображаются после синхронизации,
   а Саморазвитие и страницы Азбуки продолжают открываться.
5. При повторном зависании: шестерёнка → Диагностика →
   Отчёт о последнем сбое → Скопировать отчёт.
В новом отчёте должна быть версия 4.0-anr-index-1 и новая дата события.
Старый системный ANR может оставаться в истории Android после обновления.
