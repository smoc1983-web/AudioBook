Audiobook — возврат к поиску, ручная диагностика и название
Диагностическая ревизия: 4.0-search-return-1

ЧТО ИЗМЕНЕНО

1. Возврат к результатам поиска.
При открытии карточки сохраняются текущая выдача, текст запроса, выбранный
жанр, сведения о доступных следующих страницах и место прокрутки.
В карточке появляются кнопки «К результатам поиска». Системная кнопка
«Назад» выполняет тот же переход. Повторное нажатие вкладки «Поиск», когда
она уже открыта, также возвращает на предыдущий уровень.
Сохраняется путь через список книг цикла; история ограничена 8 уровнями.
Возврат не запускает поиск повторно, не останавливает звук и не сбрасывает
позицию воспроизведения. Нажатие названия Audiobook остаётся явным переходом
на главную. Новый поиск и новый выбор жанра начинают новую историю.
Если поиск ещё шёл в момент открытия книги, сохраняется полученная часть
выдачи. После возврата это отмечено в тексте; для обновления есть «Найти».
История выдачи хранится в памяти текущего сеанса, а не после перезапуска процесса.

2. Диагностика без окна при запуске.
Обычный запуск больше не читает и не открывает сохранённый отчёт.
После незавершённого предыдущего запуска приложение автоматически пробует
открыться без фоновой загрузки каталогов, без показа отчёта.
Если главный экран действительно не удалось создать, остаются кнопки
повторного запуска; текста/отправки отчёта на этом экране больше нет.
Запись ошибок на устройстве сохранена.
Доступ: шестерёнка → «Диагностика» → «Диагностика и логи».
По команде пользователя собираются сведения об устройстве/установленном APK,
последние события плеера и сохранённые сведения о сбое, если они есть.
Скопировать отчёт или отправить логи через выбранное приложение можно
даже без зарегистрированного сбоя. Автоматической отправки нет.

3. Название и поддержка.
В шапке, настройках и новых заголовках отчётов используется «Audiobook»,
без версии рядом с названием продукта.
Отображаемый и копируемый телефон поддержки: +79128580680.
Банки сохранены: Тинькофф, Сбербанк, Ozon.
Технический номер диагностической ревизии и реальная версия установленного
APK остаются в диагностике. Настройки versionName/versionCode не менялись.
Идентификатор пакета, папка Download/AudioBooks и формат метаданных сохранены,
чтобы обновление продолжало видеть существующие книги и настройки.

КАК УСТАНОВИТЬ В ТЕКУЩИЙ ПРОЕКТ

1. Сохраните резервную копию текущих исходников.
2. Замените MainActivity.kt: app/src/main/java/com/MainActivity.kt.
3. PlaybackService.kt приложен в последней версии и не менялся относительно
   архива Download-sound-size. Если тот архив уже установлен, повторная
   замена сервиса не обязательна; при обновлении с более старой версии замените.
4. Скопируйте app/src/main/res/values/audiobook_branding.xml из архива
   по точно такому же пути в проекте. Это дополнительный ресурс с уникальным
   именем; он не заменяет ваш strings.xml.
5. Замените app/src/debug/AndroidManifest.xml файлом из архива.
   ВАЖНО: debug находится рядом с main:
       app/src/main/...
       app/src/debug/AndroidManifest.xml
   Не создавайте main/debug. Этот файл добавляет имя «Audiobook» для debug
   приложения и MainActivity, сохраняя удаления LogSender и настройки сервиса.
6. Пересоберите :app:assembleDebug и установите полученный APK.
7. В «Диагностике» проверьте ревизию 4.0-search-return-1.

НАЗВАНИЕ ДЛЯ RELEASE И ДРУГИХ ВАРИАНТОВ

Полный app/src/main/AndroidManifest.xml вашего проекта отсутствует в
полученных исходниках. В архиве нет его замены, чтобы не потерять сервисы,
провайдеры, разрешения, значки и настройки приложения.
Для всех вариантов сборки поменяйте значение android:label в существующем
теге <application> основного манифеста на:

    android:label="@string/audiobook_product_name"

Если у запускающей <activity> или <activity-alias> есть собственный
android:label, задайте ему то же значение. Аналогично проверьте манифесты
release/flavor, если они переопределяют название.
Не добавляйте второй атрибут label: замените значение существующего.

Если доступен Python 3, приложенный rename_launcher.py выполняет это без
полной перезаписи манифеста. Сначала скопируйте ресурс из шага 4.
Из корня проекта, куда положен скрипт:

    python3 rename_launcher.py .

Это только просмотр списка изменяемых манифестов, без записи.
Для применения:

    python3 rename_launcher.py . --apply

Скрипт обрабатывает app/src/*/AndroidManifest.xml, сохраняет оригиналы
рядом как AndroidManifest.xml.before-audiobook-name и меняет только подписи
приложения/запускающих компонентов. Разрешения, сервисы и intent-filter
сохраняются. Сгенерированные файлы app/build редактировать не нужно.
Для вашей обычной debug-сборки шаги 4–5 уже задают название без скрипта.

ПРОВЕРЕНО

Структура обеих Kotlin-единиц и XML, сохранение обработчиков ошибок,
истории/параметров выдачи и прокрутки, отмена устаревших ответов,
ручной вход в диагностику, название и номер поддержки.
Пройдены регрессионные проверки удаления, очистки папок, локального
воспроизведения, таймера/встряхивания, фонового сервиса, отклика загрузок,
размеров файлов и мультимедийного звука. PlaybackService.kt совпадает
с предыдущим архивом побайтно. JavaScript-парсеры источников сохранены.
Скрипт переименования проверен на XML-примерах с launcher/alias,
отсутствующими label, комментариями, режимом просмотра и резервной копией.

Это исходники, не APK. Полного Gradle-проекта и Android SDK здесь нет;
assembleDebug, объединение манифестов и навигация на телефоне не проверялись.

— Открыть «Диагностику», скопировать отчёт и вызвать «Отправить логи».
— Проверить название Audiobook под значком и номер +79128580680 в поддержке.
