# Обновления из GitHub Releases — 4.2.90

## Первый переход

Установленные 4.2.88/4.2.89 продолжают обращаться к прежнему сайту. Публикация GitHub
сама по себе не меняет их код. Если старый feed не развёрнут заново, скачайте
[Audiobook-Preview.apk](https://github.com/smoc1983-web/AudioBook/releases/download/preview-v100090/Audiobook-Preview.apk)
один раз и установите **поверх прежней Preview, без удаления приложения и очистки данных**.
Системное подтверждение выполняет Android. Совпадение package/certificate и повышение
versionCode необходимы для обновления; фактическая установка на телефоне в этой
локальной проверке не выполнялась.

После первого перехода остаётся прежний интерфейс: Настройки → Обновления →
«Проверить обновления» → «Загрузить обновление» → «Установить загруженное обновление».
Фоновая проверка по-прежнему ограничена одним разом в сутки; ручная доступна сразу.

## Публичный контракт канала

* Источник обнаружения: https://github.com/smoc1983-web/AudioBook/releases.atom .
  Это лента последних **публичных** релизов, включающая prerelease. `/releases/latest`
  не подходит для Preview, а токен/лимит REST API не нужен. Выбирается максимальный
  числовой код своего канала, а не первый заголовок и не время публикации.
* Канал Preview: только `preview-v<versionCode>`; stable-конфигурация использует
  `stable-v<versionCode>`, свои package и имена assets. Нули в начале кода, overflow,
  дополнительные пути, query и fragment в теге запрещены.
* Описание: `/releases/download/<tag>/preview-update.json`, полный подписанный файл:
  `/releases/download/<tag>/Audiobook-Preview.apk`. URL строится приложением, а не
  берётся из произвольного поля JSON. Старые site parts в новом канале не принимаются.
* В JSON обязательны packageName, целочисленные versionCode/size, versionName,
  sha256, certificateSha256 и точное имя apk. `versionCode` должен точно совпасть с
  выбранным тегом и быть выше установленного для предложения/установки.
* Доступны только HTTPS и закреплённый репозиторий. Перенаправление asset допускается
  на `release-assets.githubusercontent.com/github-production-release-asset/1426821561/<uuid>`.
  Его временная подписанная query сохраняется, но CDN нельзя задавать начальным URL.
  Внешние хосты, другой репозиторий, userinfo, fragment и downgrade до HTTP запрещены.
  Неизвестное изменение CDN GitHub приводит к отказу, а не к ослаблению проверки.
* Ответ ленты ограничен 2 MiB, JSON — 64 KiB, APK — 200 MiB, цепочка HTTP — шестью
  запросами. Проверяются фактический размер и SHA-256 всего APK, точные package,
  versionCode/versionName, сертификат из описания и совпадение подписанта с установленным
  приложением. Подготовленный файл повторно проверяется перед запуском установщика.
* Ошибки HTTP, отсутствие нужного канала или неполный/повреждённый новый релиз — ошибка
  проверки, не сообщение «последняя версия» и не тихий откат к старому сайту.
* В приложение не входят GitHub-аккаунт, PAT или ключ подписи. SHA-256 защищает загрузку
  от повреждений; доверие к издателю обеспечивается **также подписью APK**, а не одним JSON.

## Следующие публикации

Сначала завершить проверки; затем создать новый draft с тегом и обоими assets,
после чего сделать релиз публичным. Номер должен строго возрастать; опубликованные
APK/JSON не заменять. В CI номер однажды резервируется по максимуму известных
Preview-тегов и номеру Actions; один и тот же номер сохраняется в RUNNER_TEMP
на всю попытку Actions и применяется ко всем вызовам with-release-number.sh.
AUDIOBOOK_RELEASE_RUN допускает явное задание номера для контролируемой сборки.
Ручная 4.2.90 не должна быть затёрта следующим запуском workflow. Повторная или более низкая версия
при упаковке вызывает отказ. Изменённый updater и исправления 4.2.89 находятся
в одной линии истории, без смены оформления и подписи.

## Проверки и ограничения

`PreviewUpdateRulesTest` + `PreviewUpdateHttpTest`: 22 JVM-теста. Проверяются выбор
канала/максимума, строгая связь тега и versionCode, ошибочные типы и переполнение,
неверный package/hash/размер, чужие URL, CDN redirects с подписанной query, отсутствие
Authorization, 401/403/404/429/500, лимиты чтения, повторные/вредоносные перенаправления,
оборванный/подменённый/слишком большой APK и отмена загрузки. Ещё пять Python-тестов
проверяют резервирование номера. Остальные регрессии и Android lint запускаются отдельно.

`tools/github-update-probe/` использует те же production Java-классы для живой публичной
проверки ленты → JSON → CDN → полного APK и SHA-256 без авторизации. APK затем отдельно
проверяется apksigner. Это не заменяет Android package replacement, инструментальные
тесты, Google Play Protect или проверку сохранности настоящих пользовательских данных.
