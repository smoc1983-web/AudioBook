# Обновления из GitHub Releases

Реализация проверки безопасности от 04.11.2026 находится в отдельной ветке
`cloud/recovery-github-updater-20261104`. Новый релиз этой работы не опубликован.
Исходная точка проверки — `c8301db`, опубликованная версия 4.2.91 / 100091.
Перенос с сайта уже был сделан в 4.2.90; здесь исправлены выбор релиза и проверки.

## Первый переход со старого сайта

Версии до 4.2.90 продолжают обращаться к старому сайту: публикация в GitHub сама
по себе не изменяет их код. Без отдельного обновления старого сайта нужен один
ручной APK своего канала, с прежними package и подписью, с большим versionCode.
Для установленной Preview ниже 100091 существует
[Audiobook 4.2.91](https://github.com/smoc1983-web/AudioBook/releases/download/preview-v100091/Audiobook-Preview.apk).
Установить **поверх приложения, не удаляя его и не очищая данные**.
Это существующий опубликованный APK, а не новая сборка настоящих исправлений.
После будущей согласованной публикации можно аналогично установить проверенный
новый APK напрямую, чтобы получить исправленный updater.

Preview: `com.audiobookdownloader.preview`, сертификат SHA-256
`3a4cecd14bb3e983843871766909c3f07b3dc64379800f3e270e4a27d39affb7`.
Старая стабильная `com.audiobookdownloader` — другой пакет и ключ. Preview не
обновляет её поверх и не получает доступ к её закрытым данным. Если Android
отклоняет подпись, остановиться: не удалять приложение для обхода ошибки.
Стабильного подписанного GitHub Release на момент проверки нет.

## Контракт и границы доверия

* Публичный источник: `GET https://api.github.com/repos/smoc1983-web/AudioBook/releases?per_page=100&page=N`.
  Максимум 10 страниц по 2 MiB. Если полного списка в этом пределе нет, проверка
  завершается ошибкой вместо выбора потенциально устаревшего релиза.
* Канал определяется точным тегом `preview-v<versionCode>` или `stable-v<versionCode>`,
  не флагом prerelease: опубликованный Preview 100091 имеет `prerelease=false`.
  Draft исключается. Выбирается максимальный код своего канала во всём списке;
  неполный/повреждённый выбранный релиз не заменяется старым.
* VersionName следует принятой схеме `4.2.N`, versionCode — `100000+N`.
  Правила резервирования номера, теги, applicationId и ключи не изменены.
* Оба assets берутся из объекта одного Release с положительным ID и каноническими
  тегом/адресом. Preview: `preview-update.json` и `Audiobook-Preview.apk`;
  stable: `stable-update.json` и `Audiobook.apk`. Обязательны готовое состояние
  `uploaded`, уникальное имя, положительные ID/размер и API `digest=sha256:<hex>`.
  Описание ограничено 64 KiB, APK — 200 MiB.
* JSON скачивается по точному browser_download_url своего Release; его размер и
  SHA-256 сравниваются с API digest metadata-asset. Затем JSON проверяется на
  packageName, канал через тег/имя APK, versionCode/versionName, размер, хеш и
  certificateSha256. Размер/хеш APK из JSON обязаны совпасть с независимыми полями
  APK-asset в API. Произвольные JSON URL и старые многокомпонентные site parts запрещены.
* Источник контрольной суммы — GitHub Releases API по TLS для закреплённого
  репозитория; это независимый от скачанного JSON/APK источник, не вычисленный
  самим APK «эталон». API digest не заменяет проверку Android-подписи.
* Разрешены HTTPS, точные API-страницы, download URL закреплённого репозитория и
  своего канала. Asset может перенаправляться только на
  `release-assets.githubusercontent.com/github-production-release-asset/1426821561/<UUID>`.
  Подписанная CDN query допускается только после такого перехода. API не может
  перенаправить на CDN; CDN не принимается начальным адресом. Чужой хост/репозиторий,
  HTTP, userinfo, fragment, закодированный обход пути и циклы запрещены.
* 15 с на подключение, 30 с на чтение, не более шести запросов в цепочке.
  Ограничены размеры ответов; Content-Length при наличии должен быть корректным
  и совпасть с полученными байтами. APK проверяется по фактическому размеру и SHA-256.
  401/403/404/429/5xx и квота GitHub дают понятную ошибку; автоматического
  бесконечного ожидания/повтора нет. Уничтожение экрана отменяет активное соединение.
  Временные подписанные URL и содержимое сетевых исключений не выводятся пользователю.
* После скачивания Android PackageManager извлекает package/version/signers.
  Нужен ровно один текущий подписант, совпадающий с установленным приложением и
  сертификатом выпуска, версия должна быть выше установленной и точно как в релизе.
  Несовпадение — отказ. Полную проверку APK и окончательное разрешение установки
  выполняет Android Installer; приложение не обходит отказ Android.
* Успешно проверенный API-объект и точный JSON сохраняются в закрытых preferences.
  При каждом запуске установки, в том числе после перезапуска процесса/возврата
  из разрешений, повторяются проверка сведений, размер/SHA-256 и Android identity.
  Старый кеш без такого подтверждения требуется скачать заново. Установщику
  выдаётся отдельная проверенная копия с именем по хешу через существующий FileProvider.
  Параллельная загрузка не заменяет уже переданный APK. Проверки не меняют библиотеку,
  коллекции, прогресс и настройки; отмена убирает только собственный временный APK.
* Сохранён существующий экран с одной контекстной кнопкой и темой пользователя.
  Повреждённый кеш позволяет повторно проверить/скачать обновление без зацикливания
  на кнопке установки. В приложении нет входа в GitHub, Authorization или секретов.

## Публикация и проверка

Ничего из этой ветки не публиковать без отдельного разрешения владельца.
Для будущего релиза сначала загрузить оба assets в draft, дождаться корректных
GitHub API digests, проверить их и только затем публиковать. Опубликованные APK/JSON
не заменять. Оставлен существующий механизм резервирования возрастающего номера.

Проверки: JVM-тесты выбора/канала/пагинации, схемы версии, целостности, Android identity
policy, отказов сети и адресов; обе Android-конфигурации; Debug/Release и lint;
инструментальные проверки экрана, FileProvider и полного публичного потока до
системного подтверждения без нажатия «Установить». Workflow
`github-updater-review.yml` имеет только `contents:read`, `actions:read`; не создаёт
ключи, теги или релизы, не меняет main, сохраняет только отчёты.
Фактические результаты и ограничения — в `GITHUB-UPDATER-REVIEW-2026-11-04.md`.
