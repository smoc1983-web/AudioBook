# AudioBook — постоянные правила работы между чатами

Обновлено: 2026-11-25. Этот документ — действующая инструкция для разработки AudioBook.
Исторические отчёты в AGENTS.md и docs/HANDOFF.md нельзя выдавать за текущее состояние.

## Как начинать новый чат или сеанс

1. Открыть `https://github.com/smoc1983-web/AudioBook`, прочитать этот файл,
   `docs/ACTIVE-QA.md`, `AGENTS.md`, `docs/QUALITY.md` и
   `.agents/skills/ub-mode/SKILL.md`.
2. Проверить фактическое состояние веток `main`, `test`, активной QA-ветки и PR;
   последние коммиты, проверки GitHub Actions и опубликованные релизы.
   Записи из прошлого разговора и документы не заменяют проверки по GitHub.
3. Продолжить с первого незаконченного этапа. Не просить пользователя
   повторно описывать согласованное задание и не создавать параллельную работу.
4. При завершении каждого существенного шага обновлять `docs/ACTIVE-QA.md`:
   задача → изменения → SHA → запуск Actions → результат → ошибка и исправление →
   статус публикации. Никогда не писать «готово» без подтверждения.
5. При недоступности инструментов честно указать конкретное ограничение,
   сохраняя подтверждённые результаты. Не путать завершение ответа с фоновой разработкой.

## Разработка, тестирование и выпуск

- Пользователь сообщает ошибки и пожелания; исполнитель ведёт единый журнал
  задач и устраняет ошибки до успешного результата, когда доступен инструмент
  для изменения кода и запуска CI. Без повторных разрешений для уже согласованной
  **тестовой** работы.
- Ветка `main` — основная версия: **не изменять, не объединять в неё
  изменения и не публиковать основной APK без нового явного разрешения пользователя**.
  Проверка основной ветки только для чтения допустима.
- Разработка: отдельная `qa/*` ветка с PR в `test`. В PR проходят
  автоматические проверки. Зеленый статус относится только к исполнявшимся тестам,
  не гарантирует завершённость всей функции или работу на реальном телефоне.
- При ошибке: открыть логи, определить первопричину, исправить код,
  добавить/сохранить регрессионный тест, новый коммит и новый CI-прогон.
  Не отключать тесты, не скрывать ошибки и не ослаблять проверки ради зелёного статуса.
- После реализации и успешного профильного QA, проверить совместимость,
  затем объединить в `test` — workflow
  `.github/workflows/build-test.yml` на push в `test` запускает
  автоматическую подписанную сборку и публикацию `Audiobook-Test.apk`
  через `test-v...`, **но только при прохождении всех его проверок**.
- Проверять `applicationId=com.audiobookdownloader.test`, исходный сертификат
  подписи, возрастающий `versionCode`, установку поверх старой тестовой версии,
  сохранение пользовательских данных, встроенный обновлятор.
- Для `main` сохранять исходный пакет `com.audiobookdownloader.preview`,
  старый ключ и данные; выпуск только по явной команде после тестов.

## Скиллы и качество

- При каждой новой задаче читать и применять `.agents/skills/ub-mode/SKILL.md`
  (сначала сделать работающим, затем улучшить; тест реального поведения;
  малые проверяемые изменения; журнал работы).
- Читать `docs/QUALITY.md`; по применимости использовать
  `scripts/quality-tools.py`: Crapper, Dryer, Mutator.
  Kotlin этими утилитами штатно не анализируется — это не «прошедший» тест.
- Использовать диагностику Android/Gradle, тесты парсеров, загрузок, ревью кода,
  проверку релиза и безопасность; соответствующие специализированные навыки
  применять, только если реально доступны в текущей среде.
  Не объявлять выполненным отсутствующий тест или ненайденный skill.
- Сторонние инструменты и навыки изучить на лицензии, команды, сетевые обращения,
  зависимости и безопасность перед выполнением; никаких секретов в коммитах.
- Требуемые запуски включают профильные unit/UI/Android emulator проверки,
  подпись, обновление поверх прошлого APK, поиск, плеер, коллекции и обновлятор.

## Отчётность пользователю во время одного сеанса

После значимого действия сообщать: выполнено/выполняется/ошибка/ожидается;
точный SHA, ссылку на конкретный workflow run, диагноз сбоя и следующий шаг.
Не сообщать «сборка идёт», пока GitHub не вернул ID реального запуска.
Ссылки:
- Actions: https://github.com/smoc1983-web/AudioBook/actions
- Releases: https://github.com/smoc1983-web/AudioBook/releases
- Активная задача и журнал: docs/ACTIVE-QA.md

Работа GitHub Actions после коммита действительно автономна до завершения workflow.
Но чат сам по себе не делает новые коммиты, исправления и публикации между
сообщениями без специально настроенного и реально выполняемого агента.
Расписание проверки не равнозначно автономной разработке — не путать эти вещи.

## Совместимость и контекст

- `main` и `test` — разные Android-пакеты и независимые данные.
- `README.md` и исторические части `AGENTS.md` могут отставать от релизов.
  Для актуальной версии сверять теги Releases и сведения пользователя об установке.
- На момент подготовки правил пользователь сообщил, что основная версия
  4.2.125 установлена. Следующий согласованный выпуск — только тестовый.
- Подсказка для нового чата: «Продолжай AudioBook по docs/AI-WORKFLOW.md
  и docs/ACTIVE-QA.md. Проверь GitHub и продолжай без повторных согласований».
