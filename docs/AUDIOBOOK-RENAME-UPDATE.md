Пакет остаётся **com.audiobookdownloader.preview**, сертификат — **3a4cecd14bb3e983843871766909c3f07b3dc64379800f3e270e4a27d39affb7**, каталог загрузок — **Download/AudioBooks-Preview**. Сохраняются preferences, коллекции, позиции и ранее выданный доступ к папке. Изменение имени не создаёт третьего приложения и не заменяет старую стабильную Audiobook com.audiobookdownloader.

Старая установленная 48 читает **updates/preview-update.json** и ожидает техническое имя файла **Audiobook-Preview.apk**; оба значения сохранены для совместимости. Публичный сайт и ручное сохранение файла используют отображаемое имя Audiobook. Ключи и пароли в канал обновлений не входят.

## Проверка на телефоне

1. Открыть установленную **Audiobook Preview 48**, затем **Настройки → Обновления**.
2. Нажать **Проверить обновления**. Должна появиться **4.2.50**.
3. Нажать **Загрузить обновление** и дождаться сообщения об успешной проверке. Оставить окно открытым во время загрузки.
4. Нажать **Установить загруженное обновление**. При необходимости разрешить установку из приложения и подтвердить **Обновить** в Android.
5. Открыть обновлённую **Audiobook** и проверить книги, коллекции и сохранённую папку. Приложение между выпусками не удалять.

Самостоятельная загрузка APK с сайта для этой проверки не требуется. Если установка через приложение не завершится, нужно сохранить сообщение Android/отчёт; не удалять установку для обхода ошибки.

## Автоматическая проверка

В CI сохраняется последний опубликованный APK 48 и его manifest, сверяются размер/хеш/сертификат. В одноразовом Android 36 эмуляторе отдельно устанавливается настоящий APK 48, создаются контрольные preferences, коллекция, путь выбранной папки и приватный файл, выдаются разрешения аудио/уведомлений. Новая instrumentation проверяет кандидат вызовом **PreviewUpdater.verifyApk** из установленной старой версии и проверяет его новое имя через PackageManager. Затем Android выполняет реальную замену пакета через **adb install -r**; новая instrumentation проверяет имя, сохранность контрольных данных/разрешений и запуск MainActivity.

Это проверка нативной проверки кандидата и сохранения данных при замене пакета, не автоматическое нажатие трёх кнопок/согласия на физическом Samsung. Настоящая загрузка и установка через интерфейс телефона будут подтверждены владельцем после публикации. Путь библиотеки в fixture проверяет сохранность настройки; настоящий SAF-доступ к пользовательской папке в эмуляторе не выдаётся.

Два теста UpgradeCandidateTest запускаются отдельными проходами против старого и нового APK; в общем startup-прогоне они намеренно пропускаются без специальных аргументов. Остальные восемь Android-проверок остаются обязательными. Публикация допустима только после успешного завершения обоих проходов.

Окончательные результаты и хеши сохранены в verification/checks-100050.json и installed-upgrade-100048-to-100050.json.
