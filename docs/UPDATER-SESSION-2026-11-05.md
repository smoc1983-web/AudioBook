# Задание обновления: этап 9, без публикации

Найдена причина потери загрузки: PreviewUpdatesActivity.onDestroy вызывал
cancel и shutdownNow собственного executor. Теперь UpdateSessions хранит одно
задание на applicationContext. Окно подписывается на снимок в onStart и снимает
подписку в onStop; поворот или возврат показывают тот же результат и прогресс.
Повторный запуск занятой операции отклоняется. Явная кнопка отмены разрывает
HTTP и не разрешает запоздалому результату запросить установку.

APK и метаданные по-прежнему получает PreviewUpdater из одного подходящего
GitHub Release. GitHubReleaseCatalog, PreviewUpdateRules, UpdateApkPolicy,
проверки PackageManager, приватный receipt, хешированная копия установщика,
подпись, размер/SHA-256 и границы HTTP не ослаблены. Идентификаторы пакетов,
каналы, ключи и версии не менялись. Старый hostname не исправляется этим
изменением: ограничение перехода с amplecoot2048 описано в BRIDGE-4.2.93.md.

Загрузка сама не открывает установщик. Только явная команда установки
проверяет файл и создаёт одноразовый запрос, который может забрать видимое
возобновлённое окно. Возврат из разрешения неизвестных источников повторяет
проверку APK. Activity не удерживается фоновым заданием.

Ограничение: задание сохраняется при пересоздании/закрытии окна в живом процессе.
Это не отдельный foreground download service или докачка после убийства процесса
Android. Готовый APK/receipt остаются в прежнем кэше; неполный APK не принимается,
при следующем запуске доступна повторная загрузка. Приложение и книги не удаляются.
