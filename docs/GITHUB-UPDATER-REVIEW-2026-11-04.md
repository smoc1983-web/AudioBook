## Найдено и исправлено

1. Atom показывает ограниченную последнюю выборку: один канал мог вытеснить другой.
   Новый `GitHubReleaseCatalog` проходит публичный REST API постранично, выбирает
   максимальный код своего канала, исключает draft, проверяет ID/тег/репозиторий и
   готовые уникальные assets одного Release. При превышении лимита/повреждении
   выбранного выпуска — отказ, без молчаливого выбора старого.
2. Хеш APK раньше брался только из скачанного JSON. Теперь обязательны независимые
   GitHub API `asset.digest` для JSON и APK: сначала сверяется сам JSON, затем его
   размер/хеш APK с API, затем фактические байты APK. Нет доверия к «эталону»,
   вычисленному из самого недоверенного APK/JSON. Источник доверия — закреплённый
   публичный GitHub-репозиторий/API по TLS плюс оригинальная Android-подпись.
3. Кеш повторно проверялся только на package/code/signer. Теперь закрытое подтверждение
   релиза сохраняется только после успешной загрузки; перед каждой установкой
   повторяются проверки метаданных, размера, SHA-256 и Android identity. Без подтверждения
   требуется повторное скачивание. Android PackageManager предоставляет сертификаты,
   подписант должен совпасть с установленным и с сертификатом релиза. Окончательную
   криптографическую проверку и разрешение замены выполняет Android Installer.
4. Между проверкой и Installer общий cache path могла заменить параллельная загрузка.
   Installer получает отдельную повторно проверенную копию с именем SHA-256.
5. HTTP-соединение могло остаться открытым при ошибке получения статуса.
   Закрытие перенесено в finally; добавлены явная отмена активного соединения,
   обнаружение циклов, строгий UUID CDN своего repo, проверка Content-Length и encoding,
   понятные ошибки квоты/429/таймаутов и скрытие сырых сетевых URL в ошибках.
6. После отказа проверки кеша можно заново проверить и скачать обновление той же
   контекстной кнопкой. Сохранились существующие тема, расположение и состояния UI,
   обработка разрешения установки и возврата из Android.
7. Обновлены устаревшие тесты InstallerLaunchTest: прямой запуск непроверенного
   кеша теперь должен отклоняться. Новый сетевой Android-тест проходит весь
   production-поток до системного подтверждения и проверяет отказ после порчи кеша.

Используется только анонимный HTTPS GET. В APK/код/репозиторий не добавлены токены,
пароли или приватные ключи. CI восстанавливает существующий ключ из уже имеющегося
секрета/кеша, отказывается работать без него и не генерирует замену. Артефакты CI —
только отчёты. Удаляются только собственные временные APK отменённой операции;
библиотека, коллекции, прогресс и настройки пользователя не затрагиваются.

## Переход и ограничения

Старый код до 4.2.90 не переключится на GitHub сам. Минимальный безопасный путь —
один раз вручную скачать подписанный APK своего пакета/канала с более высоким
versionCode и установить поверх, без удаления приложения и очистки данных.
Для старой Preview подходит существующая 4.2.91; она уже получает обновления
из GitHub, но ещё не содержит усиления этой ветки. Исправления появятся у пользователя
только после отдельного разрешения и последующей публикации нового проверенного APK.
Обновить исходную stable 1.0 сборкой Preview невозможно: это другой пакет/подпись.
Полная инструкция и ссылка на существующую .91 — `GITHUB-UPDATES.md`.

Ветка подписи Android до API 28 отдельно на эмуляторе не запускалась; нативная
проверка выполнена на API 36. На физическом телефоне установка, сохранность настоящей библиотеки, работа
Play Protect/Samsung и установка через старый сайт в этой задаче не проверялись.
Даже успешный тест окна Installer не равен проверке фактической замены пакета.
Неподписанный APK или APK с другим ключом не предлагаются как обход проблемы.
