## Поведение

Плеер → «Закладки» → «История перемоток».

Перед ручной перемоткой сохраняются прежняя позиция, запрошенная новая позиция,
устойчивые editionId/chapterId, случайный ID записи и время устройства. Учитываются
ползунок, кнопки перемотки и команды seek MediaSession/системного плеера. Автоматическое
начало/восстановление главы, откат после паузы и обычное прослушивание историю не пополняют.
Кнопки смены главы и переходы по закладкам не являются записями этой истории.

Всего сохраняются 50 последних точек на устройстве, в порядке команд, без сортировки
по часам. В окне видны только точки текущего издания, по десять с догрузкой списка.
50 — общий предел для всех изданий, а не по 50 на каждую книгу. Нулевой переход
не добавляется. В истории нет адресов аудио, токенов или аккаунтов.

«Вернуться» использует позицию перед выбранной перемоткой. Плеер повторно проверяет
ID записи и соответствие текущему изданию/главе; сохранённый индекс не используется.
Можно вернуться в другую главу того же плейлиста, в том числе после перестановки глав.
Другая озвучка, отсутствующая/неоднозначная глава или заведомо слишком короткая запись
не получают чужую позицию. Если длительность ещё неизвестна, остаётся обычное ограничение
позиции после подготовки MediaPlayer. Возврат не порождает новую запись истории.

Пауза сохраняется: возврат из приостановленного плеера не запускает звук. При играющем
плеере воспроизведение продолжается. Скорость и минутный таймер используют существующий
механизм; при смене главы действует прежняя отмена таймера «до конца выбранной главы».
Существующие файлы, очереди, коллекции, закладки и ID не изменяются.

История хранится отдельно в private SharedPreferences `seek_history_v1`; изменения
записываются через apply, без новой периодической работы и синхронного commit в плеере.
Это история конкретного устройства: она не добавлена в резервные копии или обмен SAF.
Сброс истории текущего издания требует подтверждения и сохраняет точки остальных изданий.
При повреждённом JSON запись новых точек останавливается, исходное значение не заменяется
пустым списком. Подтверждённый сброс сначала сохраняет оригинал в поле damaged того же
хранилища. Значение неподходящего типа автоматически не исправляется и остаётся сохранённым.

Синхронная ошибка native seek возвращает прежнюю позицию и не добавляет точку истории.
Сам факт принятой команды seek не является подтверждением успешной передачи сетевого звука:
история хранит место перед командой, а не журнал декодирования.

### Обнаруженная совместимость API23

CI44122287510: verify и native36 прошли; native23 — 4 ошибки из34. Logcat показывал
pause called in state8 (Prepared), error(-38,0), после чего MediaPlayer освобождался.
Причина в прежнем applySettings: setPlaybackParams не обязан начинать воспроизведение
на Android6, а логический isPlaying=false приводил к безусловному pause в Prepared.
Добавлена проверка фактического player.isPlaying перед pause. Это исправление
предусловия системного API, не подавление ошибки. Отдельный native-тест проверяет
подготовку, скорость на паузе и повторный Play. Остальные прежние ассерты сохранены.

### Ошибка первого запуска CI, отделённая от функциональных тестов

CI44120323342 запускал строки emulator-runner в отдельных shell-процессах: переменная
списка классов исчезла до Gradle. Пустой filter запустил весь исторический native-набор,
что не было планом этого шага. На API36 наблюдались пять отказов:

- NotificationSettingsTest: ATD-образ без полноценного Settings (в отдельном фиксе
  уведомлений использовался полный google_apis, где тест проходил).
- QueueProcessTest: две стадии требуют внешнего HTTP-сервера, последовательных вызовов,
  force-stop и реального reboot между ними; запуск всего класса сразу этого не делает.
- StartupSmokeTest.mainNavigation: прежний список «14 источников» отвергает Lis10,
  давно добавленный в приложение; assertion устарел, для этой функции не переписывался.
- StartupSmokeTest.playerAdds: сценарий ждёт внешнюю инъекцию акселерометра; текущий
  workflow её не выполнял. Причина не объявляется исправлением плеера.

Причина конфигурации исправлена: выбор классов и Gradle теперь выполняются внутри
одного native-tests.sh с непустым аргументом. Локальный стенд с подставным Gradle
подтверждает сохранность одного аргумента class filter для обоих API (7/8 классов).
Ожидания/ассерты старых тестов не отключены, их специальные workflows не менялись.
Эти результаты не выдаются за успешный полный исторический набор. Следующие CI
проверяют заявленные новые классы и перечисленные регрессии.

## Ограничения и продолжение

Физический телефон, реальная гарнитура/OEM, убийство процесса/перезагрузка телефона,
Android Installer, измерения батареи/памяти не проверены. Пересоздание службы не следует
выдавать за восстановление после выключения устройства. Автоматическая запись через apply
не является обещанием сохранения последней команды при аварии накопителя.
Обычный таймер/idle проверяется регрессиями, экономия батареи не заявляется.

Это ещё один шаг этапа8, а не завершение всех его пунктов. Следующий небольшой пакет —
мониторинг доступности источников. Остальные незавершённые функции перечислены в
DEVELOPMENT-STAGE-8.md. Публикация только после отдельного разрешения.
