# Этап8: следующий том по Wi-Fi с согласием

Рабочая ветка `cloud/next-volume-wifi-20261118`, чистая база `b3bef0b`, fetch/remote
проверены. Публичный Preview4.2.95, source main, package/version/signing прежние.
Релиз не публикуется. ub-mode разрешён для текущего этапа8; TokenEconomizer CLI
использован (sessions0, hooks/token savings не подтверждены).

## Как пользоваться

Плеер → «Серия» → «Следующий том по Wi-Fi». Нужны ранее проверенные сведения
аудиоисточника: добавьте книгу в коллекцию/отслеживание, проверьте продолжения и
при необходимости обновите сведения аудиоисточника. Само открытие панели не
запускает новый фоновый поиск. Используется сохранённый список этого seed URL.
Если источник не подтвердил автора, прямую серию и соседний номер, кнопка недоступна;
ручной поиск и обычное скачивание остаются доступны.

Показываются только целые положительные тома N+1 из того же аудиоисточника,
с совпадающими автором/серией. Разные озвучки предлагаются явно, до10 вариантов;
автоматического выбора одной записи нет. Личные подписи серии и имена файлов
не доказывают связь. Литрес/Author.Today в этой функции служат справочниками,
не источником автоматического получения платных файлов.

После выбора проверяются страница и список глав. Показываются книга, автор,
серия/номер, источник, число глав и полный известный кэшированный размер либо
«неизвестен». Число глав и размер не доказывают полноту записи. Дополнительных
HEAD-запросов аудио ради размера новая панель не делает.

Кнопка «Разрешить загрузку этого тома по Wi-Fi» разрешает только выбранный том.
Аудио загружается через существующую устойчивую очередь и Android DownloadManager:
только Wi-Fi, без лимитной сети/роуминга. Проверка страницы/метаданных выполняется
при открытии на текущем соединении, которое может быть мобильным. Прослушивание
не переключается; прогресс, скорость и текущая глава не сбрасываются.

Android может отложить выполнение. Закрытие приложения не отменяет уже сохранённую
очередь. Отмена подтверждённой загрузки — в существующем разделе загрузок;
закрытие/отмена окна до подтверждения не создаёт заданий. Удаление seed из коллекции
не отменяет уже отдельно разрешённую загрузку. Разрешение не распространяется на
следующие части цикла: для нового тома нужно новое подтверждение.

## Проверки и восстановление

- Выбор основан на source author/series/whole order, seed URL и томе N+1; без
  угадывания по названию и без подмены другим сервером. Несколько прямых циклов
  с конфликтом номера не дают автоматического предложения.
- Перед подтверждением источник должен заново передать те же URL издания,
  название/автора, ссылку серии и номер. Перед постановкой повторно проверяются
  сохранённые сведения seed. Изменение кандидата останавливает постановку.
- Демо, HLS/DASH, пустой/некорректный список и коллизии безопасных имён глав
  отклоняются. Известный существующий валидатор проверяет фактические скачанные
  файлы. Не обещаны полное декодирование, отсутствие скрытого пробника на любом
  сайте или обход защиты/платного доступа.
- В QueuedChapter добавлен optional boolean wifiOnly. Старые записи без поля
  читаются как false, неверный тип вызывает обычное защищённое восстановление
  очереди. Retry/link refresh сохраняют флаг. Общая настройка не ослабляет его.
- Постановка повторного разрешения использует прежние ID глав; существующий механизм
  проверяет/повторно использует готовые файлы. Текущая ручная загрузка не переименовывается
  в Wi-Fi: конфликт сообщается без её удаления.
- При восстановлении окна нет повторной отправки после успешного подтверждения.
  Сбой очереди показывает ошибку и оставляет повтор. Crash после фактической записи,
  но до отображения успеха, допускает повтор с теми же устойчивыми ID, без новых глав.
- Crash window между системным enqueue и сохранением job ID: активное старое задание
  принимается для Wi-Fi intent только с собственным Wi-Fi маркером description,
  выставленным вместе с mask; завершённое может пройти обычную проверку/повторное
  использование. Сеть чужого/неподтверждённого активного задания не угадывается.
- Legacy mapping `download_job_<id>` дополняется Boolean `download_wifi_only_<id>`
  в той же записи; recovery не теряет ограничение, если строки очереди нет в
  восстановленном snapshot. Повреждённый тип не превращается молча в false.
  Эти runtime mappings не экспортируются в backup; обе записи чистятся вместе.
- Для свежих сведений следующего тома используется отдельный чистый парсер:
  ссылка принимается только для book page того же зарегистрированного источника
  и разрешённого series route. Внешние/private/file URLs не принимаются.
  Общий парсер каталога и его поддержка дополнительных источников не меняются.

## Компоненты и границы

NextVolumeRules.java, NextVolumeWifi.kt, NextVolumeWifiPanel.kt — новые компоненты.
MainActivity.kt: точечное включение в панель серии, source evidence, параметр
DownloadManager; прежние Java constructors/signature сохранены @JvmOverloads.
PersistentDownloads.kt: флаг/JSON/retry/adoption/mapping. PlaybackService/widgets,
APK updater, сборочные зависимости, manifest и подпись не изменены.

Не проверены физический телефон/OEM, реальное переключение mobile↔Wi-Fi/VPN,
перезагрузка/processkill/powerloss/diskfull, живые сайты в новом UI и installer.
В тестах — фиксированные источники и чтение сохранённого snapshot, не аппаратная
перезагрузка. На API36 проверяется фактическая системная запись сети. На API23 private columns
DownloadProvider недоступны: проверяются сериализованные Android настройки общей
production Request-конфигурации (test-only reflection до hidden-API enforcement)
и публичное описание фактически созданного задания. Проверки не пропущены,
но прямое чтение маски реального job на API23 не утверждается.
Ограничение маски проверяется отдельно от реальной смены сети.

Периодическая работа worker/recovery осталась прежней: CONNECTED constraint,
опрос существующей очереди каждые2.5с в пределах8мин с retry. При ожидании Wi-Fi
это может давать лишнюю фоновую работу; оптимизация scheduling отдельна. Экономия
батареи/RAM не измерялась и не заявляется. Старые signed URL могут истечь до Wi-Fi;
работает прежний ограниченный link refresh, не каждый источник его поддерживает.

Этап8 целиком не завершён. Следующий пакет после подтверждения — дополнительные
фильтры поиска; автоматический облачный progress sync в текущем плане остаётся
ручным SAF/Яндекс exchange по прежнему выбору пользователя.
