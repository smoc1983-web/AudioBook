# AudioBook: совместимость обновлений и контроль подписи

Дата проверки: 2026-11-23. Исходная точка: опубликованный релиз `preview-v100100` (4.2.100), commit `f9a3efe31db266aea66100092e2157a887577b9f`.

## Приоритет продукта: Stable — основная, Preview — только испытания

На 2026-11-23 владелец уточнил: Preview использовалась только для тестовых версий; **цель разработки и обновлений — установленная Stable Audiobook**. Для каждого следующего изменения сначала тестовая сборка в изолированном пакете, затем перенос в Stable только после регрессии и сверки подписи.

- **Stable**: package `com.audiobookdownloader`, ожидаемый сертификат установленной исходной версии `020e6c23aad35b45e6ef2ee3ef3326a6ddac731b8491162f0d340848887c9bc7`, локальный первоначальный keystore в Code on the Go (`$HOME/.android/debug.keystore`, alias `androiddebugkey`), согласно `docs/STABLE-INSTALL.md`. Сам закрытый ключ не найден в GitHub и его наличие на телефоне нужно проверить перед выпуском.
- **Preview**: package `com.audiobookdownloader.preview`, другой сертификат `3a4cecd14bb3e983843871766909c3f07b3dc64379800f3e270e4a27d39affb7`. Проверка 4.2.99→4.2.100 годится только для Preview и **не подтверждает** обновляемость установленной Stable.
- Не публиковать готовый Stable APK и не обновлять Stable, пока не сверены **настоящие** сертификаты оригинального установленного APK и ключа, версия и версия кандидата. Сборка неподписанного Stable-кандидата не считается готовым обновлением.
- Сохранение настроек/книг/прогресса подтверждать на стабильном package. Стабильную установку не удалять и данные не очищать.

## Подтверждённый сценарий 4.2.99 → 4.2.100

Workflow `Verify and package Audiobook Preview 4.2.100`, run [44983744201](https://github.com/smoc1983-web/AudioBook/actions/runs/44983744201), завершился успешно. Он:
- восстановил оригинальную идентичность Preview из защищённого секрета/восстановленного signing cache;
- сравнил SHA-256 сертификатов старого и нового APK;
- подтвердил увеличенный `versionCode`: `100099 → 100100`;
- проверил выдачу системного подтверждения установки из старого приложения;
- установил новый APK поверх старого через `adb install -r` в одноразовом эмуляторе;
- подтвердил сохранение настроек, коллекций, личного файла аудио и контрольной суммы.

Публикация run [44984658067](https://github.com/smoc1983-web/AudioBook/actions/runs/44984658067) тоже прошла успешно; её лог содержит `certificateSha256`, `versionCode: 100100` и `versionName: 4.2.100`.

**Предел проверки:** фактическое скачивание обновления по сети внутри установленного приложения на физическом телефоне и подтверждение Google Play Protect здесь не тестировались.

## Блокирующие условия для каждого нового Preview-релиза

1. Использовать исходник не старее `preview-v100100`; не собирать релиз прямо из отставшей `main`.
2. Пакет строго `com.audiobookdownloader.preview`. `versionCode` **строго больше** текущего опубликованного (`100100` на дату этой проверки).
3. Подписывать оригинальным ключом Preview. Не создавать новый ключ, если восстановление невозможно.
4. `apksigner verify --verbose --print-certs`: сертификат SHA-256 равен `3a4cecd14bb3e983843871766909c3f07b3dc64379800f3e270e4a27d39affb7`, APK Signature Scheme v2 доступна.
5. `preview-release.py` обязан сравнивать отпечаток **и с эталонным значением, и с предыдущим опубликованным обновлением**. При несовпадении остановить публикацию.
6. Тест `test-preview-upgrade.py` должен пройти от последней публичной версии к новому кандидату, включая проверку сохраняемых данных.
7. Метаданные `preview-update.json` должны описывать именно подписанный APK: пакет, `versionCode`, версию, SHA-256 самого файла, сертификат, URL/имя и commit.
8. Публиковать только новый tag и assets; не перезаписывать существующий release. Проверить обнаружение обновления старым приложением.

## Stable

Для `com.audiobookdownloader` нужны подлинный старый сертификат и ключ: `scripts/sign-phone-update.sh` проверяет SHA-256 отпечаток исторического сертификата. Наличие рабочего Preview-ключа **не доказывает**, что Stable можно обновить. До подписания очередной Stable-сборки нужно сравнить сертификат установленного Stable APK с доступным оригинальным keystore и проверить более высокий `versionCode`.

Нельзя просить пользователя удалять приложение или стирать его данные для решения ошибки подписи.

## Управление ветками

На дату проверки `main` = `c8301db` и является предком `preview-v100100` на 232 коммита. Для безопасной синхронизации готовить отдельный draft PR из интеграционной ветки, основанной на последнем подтверждённом релизе. Эксперименты 2026-11-23 с поиском и группировкой серий (`cloud/search-*`) не входят в 4.2.100 и должны проходить независимые проверки перед переносом.

Никогда не коммитить keystore, пароли, base64-ключи или исходные установленные APK в общедоступный репозиторий.
