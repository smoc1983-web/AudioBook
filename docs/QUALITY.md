# Правила разработки ub-mode

Пожелание пользователя от 27.10.2026: применять ub-mode при следующих изменениях.
Постоянная точка входа — корневой AGENTS.md, точная инструкция —
[SKILL.md](../.agents/skills/ub-mode/SKILL.md). Версии инструментов закреплены
коммитами и SHA-256 архивов в [tools.lock.json](quality/tools.lock.json).

## Установка и запуск

На машине разработчика нужен Python 3.12+, интернет и обычный доступ к PyPI/GitHub:

```bash
python3 scripts/quality-tools.py install
python3 scripts/quality-tools.py crapper --no-coverage app/src/main/java
python3 scripts/quality-tools.py dryer --threshold 0.8 app/src/main/java
python3 scripts/quality-tools.py mutator --scan app/src/main/java
```

Инструменты изолированы в .quality-tools и не входят в APK. Системные пакеты,
ключи, applicationId, versionCode и хранилище книг не изменяются. Переустановка
повторяет закреплённые версии. Tree-sitter-language-pack загружает грамматики
при первом анализе; их доступность требует сети и не обещается в офлайн-среде.

## Применение к изменениям

Отдельный workflow `.github/workflows/quality.yml` запускает анализ Java при
соответствующих push в main, pull request и вручную. Он сохраняет EDN-отчёты,
но не публикует APK и не объявляет mutation scan полноценным mutation testing.

1. Воспроизвести проблему и определить проверяемый результат. Для исправления
   ошибки сначала получить честный падающий тест, когда это практически возможно.
2. Сделать небольшое изменение, запустить профильные JVM/Android/JS проверки.
3. Запускать Crapper и Dryer на поддерживаемых исходниках, Mutator сначала
   на одном изменённом файле. Сохранять команды, результаты и ограничения.
4. Полный mutation run требует явно заданного реального теста, который исполняет
   этот файл. Для Java здесь Gradle, а стандарт Mutator — Maven: обязательно
   передать --test-command с профильной Gradle/JVM командой. Никогда не использовать
   команду публикации, подписи APK, git push или деплоя как тест мутанта.
5. Для мутаций общий Gradle build/cache может конфликтовать между workers:
   начинать с --max-workers 1. Тайм-аут/ошибка компиляции считается killed самим
   инструментом, поэтому изучать причины, а не объявлять тесты исчерпывающими.
6. Сохранить краткий журнал и проверенные изменения в книжном репозитории.

Цели инструкции: CRAP < 10 и разбор дублирования с похожестью >= 0.8.
Это цели для исправляемого кода, а не заявление, что исторический проект уже
соответствует им. --no-coverage показывает только сложность: CRAP и покрытие N/A,
это не прохождение CRAP gate. При настоящем измерении Java передать свежий JaCoCo
XML/команду его создания; JUnit XML не является отчётом покрытия. Dryer возвращает
0 даже при найденных кандидатах: отчёт необходимо прочитать вручную.

## Реальные границы поддержки

| Инструмент | Java | Python | Отдельный JS/CJS | Kotlin |
|---|---|---|---|---|
| Crapper | да | да | да | нет |
| Dryer (закреплённая версия) | да | да | нет | нет |
| Mutator | да | да | да | нет |

Встроенный в строки Kotlin JavaScript автоматически не извлекается этими
инструментами. Существующие JS fixtures и реальные Android-тесты сохраняются.
Пустой результат для Kotlin/JS не выдавать за анализ этих файлов.

UML Viewer — отдельный необязательный графический инструмент: для текущего
Android-проекта не установлен, его документированные сканеры не покрывают
Java/Kotlin. Метрики сохраняются в совместимом EDN, но схема Android из них
автоматически не строится. Сам ub-mode не является гарантией отсутствия ошибок.
