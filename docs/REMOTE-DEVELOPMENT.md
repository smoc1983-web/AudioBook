# Основной ноутбук и резервная облачная разработка

Настройка владельца от 2026-11-01: основная работа выполняется на Windows-ноутбуке
DESKTOP-QG19B0C через удалённый Codex. Телефон передаёт задания, файлы и процессы
сборки находятся на ноутбуке. GitHub служит резервом и точкой продолжения в облаке.

## Как выбрать среду перед задачей

1. Проверить настоящее состояние подключения ноутбука в Codex / Remote.
2. Выполнить `python scripts/check-development-host.py` в клоне репозитория.
   Скрипт загружает отметку связи из `backup/audiobook-laptop`, не меняя рабочие
   файлы, текущую ветку или индекс. Коды возврата: 0 — свежая отметка,
   10 — старше 15 минут, 20 — проверка не удалась. Свежая отметка подтверждает
   загрузку в GitHub, но сама по себе не доказывает доступность удалённого Codex.
3. Если ноутбук действительно доступен, выполнять задачу на нём. Не запускать
   дублирующую задачу в облаке. Существующий облачный чат сам не становится
   локальным: для локальной работы выбрать подключённый ноутбук в интерфейсе.
4. Если подключение недоступно, продолжать в облачной среде Codex из последнего
   успешно загруженного снимка. Перед началом сообщить его время и наличие
   `untrackedNotBackedUp`: эти новые файлы в резерв не попали.

## Продолжение при отключённом ноутбуке

В облачном Codex открыть этот репозиторий и выполнить:

```sh
git fetch origin refs/heads/backup/audiobook-laptop
git switch -c cloud/recovery-YYYYMMDD-HHMM FETCH_HEAD
```

Подставить уникальную дату/время в имя ветки. Использовать отдельную рабочую копию
или worktree, если текущая копия содержит изменения. Сначала прочитать AGENTS.md,
актуальный docs/HANDOFF.md и `.remote/heartbeat.json`. Резерв может содержать
незаконченную работу; это не проверенный релиз. Сохранить исходную подпись APK,
идентификатор пакета и пользовательские данные. Выбор ub-mode перед новой
задачей приложения остаётся обязательным по прежним указаниям владельца.

Облачные изменения отправлять в собственную ветку `cloud/recovery-*`.
В `backup/audiobook-laptop` пишет только ноутбук. Не перезаписывать её, не делать
force-push и не публиковать релизы только потому, что выполнено переключение.
Когда ноутбук вернулся, сначала сопоставить последний локальный снимок и облачную
ветку. Перенести облачные коммиты в отдельную локальную ветку, разрешить конфликты,
проверить результат и только затем возвращать выполнение на ноутбук. Не применять
автоматический reset/checkout/pull поверх незавершённых локальных изменений.

## Что автоматически сохраняется

Локальный фоновый процесс примерно раз в 5 минут создаёт снимок в отдельной ветке
`backup/audiobook-laptop` и записывает время UTC в `.remote/heartbeat.json`.
Снимок включает изменения отслеживаемых файлов и новые исходники/документы/обычные
изображения до 10 МБ каждый, с учётом .gitignore. Ключи, `.env*`, local.properties,
файлы с именами secret/token/credential и пакеты APK/AAB исключаются. Прочие новые
файлы перечисляются в `untrackedNotBackedUp`. Проверять этот список, если для
задачи нужны новые бинарные ресурсы или нестандартные расширения.

Создание снимка использует отдельный индекс и git commit-tree: рабочая ветка,
пользовательский индекс и незавершённые изменения остаются на месте. Ветка
main не обновляется фоновым копированием. Публикация использует обычный push;
конкурирующая запись вызывает ошибку, а не перезапись истории.

При недоступном интернете попытки повторяются на следующих циклах. Во время
отключения питания процесс не работает. Потеря ещё не отправленных изменений
возможна: после аварии доступен последний успешный снимок. Файлы на диске
ноутбука могут сохраниться и быть восстановлены после его включения.

## Локальная среда

- Репозиторий: `C:\Users\иван\Documents\Codex\2026-11-01\audiobook\outputs\AudioBook`.
- Java 17, Gradle 8.9, Android SDK API 36, Build Tools 35.0.0, ADB установлены.
- `JAVA_HOME` и `ANDROID_HOME` заданы для пользователя Windows.
- `scripts/windows-development.ps1` обновляет окружение процесса из настроек
  пользователя и запускает Gradle. Без аргументов проверяет версию; для сборки
  использовать `-GradleArguments @(':app:assembleDebug')` после постановки задачи.
  Передаётся `-Pandroid.overridePathCheck=true`, потому что путь содержит кириллицу.
  В этой задаче сборка приложения и установка APK на телефон не выполнялись.
- Дополнительный редактор: https://vscode.dev/tunnel/audiobook-laptop
- Tailscale: `100.92.141.29`, режим работы без входа пользователя включён.
- VS Code Tunnel и процесс обслуживания запускаются после входа в Windows.
  Резервное копирование запускает задача Планировщика Windows
  `Audiobook Host Maintenance`, независимо от процесса Codex. Закрытие Codex
  не должно останавливать резервное копирование. Старый запуск копирования через
  пользовательский раздел Run заменён этой задачей.
  После перезагрузки войти в учётную запись; ноутбук должен иметь питание и сеть.
  Сон при питании от сети отключён. Крышку держать открытой.
- Удалённым доступом Codex управляет настольное приложение. Держать его открытым.
  Запуск после входа в Windows зарегистрирован как Audiobook Codex Desktop через
  установленный пакет OpenAI.Codex; фоновые копии запускаются отдельным процессом.
  Фоновый скрипт запускает только резервное копирование. Не запускать одновременно
  `codex remote-control start` в отдельном CLI-демоне: при одном enrollment это
  вызвало конфликт HTTP 409 «Remote app server already online». У отдельного
  управляемого CLI-демона remote control отключён; само настольное подключение
  остаётся включённым.

## Граница автоматизации

Автоматизированы резервные снимки, отметка связи и локальный запуск обслуживания.
Проверку маршрута и выбор доступного хоста применять при каждой новой/продолжаемой
задаче. Уже выполняющийся чат на отключившемся ноутбуке не может сам перенести
себя в облако. В таком случае открыть облачный Codex и продолжить из резервной
ветки. Для полностью автономного запуска задач во время отключения ноутбука
потребовался бы отдельно настроенный облачный диспетчер; здесь он не создавался.
