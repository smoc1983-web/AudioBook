# Установка поверх стабильной Audiobook 1.0

Стабильную Audiobook не удалять, данные приложения не очищать. Готовые аудиофайлы остаются в Download/AudioBooks; пакет обновления — com.audiobookdownloader. Preview устанавливается отдельно.

## Исправленный скрипт для Code on the Go

1. Сохранить актуальный `scripts/sign-phone-update.sh` на телефон под именем **sign-phone-update-fixed.sh**. Скрипт из первоначального архива версии 38 устарел.
2. Положить скрипт и `Audiobook-stable-UNSIGNED.apk` в «Загрузки». Извлечённый старый APK Audiobook 1.0 также положить туда, если Android не разрешает читать установленный APK напрямую. Имя старого файла может быть любым.
3. В терминале Code on the Go выполнить:

```sh
bash /sdcard/Download/sign-phone-update-fixed.sh /sdcard/Download/Audiobook-stable-UNSIGNED.apk
```

Ввести проверенный пароль хранилища: ввод скрыт. На запрос пароля закрытого ключа нажать Enter, если он такой же. Если пароль ключа другой — ввести его отдельно. Значения не записываются в скрипт, файлы паролей или GitHub. Не вставлять их в команду запуска.

После сообщения **ГОТОВО** открыть `/sdcard/Download/Audiobook-update.apk` и выбрать **Обновить**. До успешной проверки этот установочный файл не появляется. При ошибке стабильное приложение и исходный ключ остаются без изменений. Если файл Audiobook-update.apk уже существует, он не перезаписывается.

## Что исправлено и проверяется

Пользователь подтвердил исходное хранилище `$HOME/.android/debug.keystore`, alias `androiddebugkey`, тип PKCS12. Публичный SHA-256 сертификата установленной Audiobook 1.0:

`02:0E:6C:23:AA:D3:5B:45:E6:EF:2E:E3:EF:33:26:A6:DD:AC:73:1B:84:91:16:2F:0D:34:08:48:88:7C:9B:C7`

Сам закрытый ключ на сервер не передавался. Скрипт не конвертирует и не перезаписывает хранилище. Старый вариант полагался на стандартные запросы паролей apksigner; исправленный явно задаёт `--ks-type PKCS12`, `--ks-pass env:…` и `--key-pass env:…`. Оба пароля передаются процессу отдельно, без значений в аргументах. Если доступен SDK jar, apksigner запускается через тот же JDK, что и keytool, для согласованной поддержки PKCS12.

Сначала проверяются applicationId обоих APK, повышение versionCode, подпись старого APK и её совпадение с подтверждённым сертификатом. После подписи проверяются v1/v2/v3 подписи инструментом apksigner, точное совпадение сертификатов старого и нового APK, неизменность пакета/версии и выравнивание ZIP. Только затем готовый APK переименовывается в итоговый файл на той же файловой системе. Скрипт ничего не устанавливает и не удаляет.

Если обычный путь ключа отличается, поддерживаются AUDIOBOOK_SIGNING_KEYSTORE и AUDIOBOOK_SIGNING_ALIAS. Вторым аргументом можно явно передать путь к старому APK. Само хранилище не нужно публиковать или передавать из Code on the Go.

## Проверка исправления

`scripts/tests/test-phone-signing.py` проверяет настоящий Android SDK build-tools 35 apksigner и временные PKCS12-ключи. Пароли генерируются случайно; временные ключи удаляются после проверки и не публикуются. Проверены одинаковые/разные пароли хранилища и закрытого ключа, оба неверных пароля, чужой сертификат, неподходящий пакет, отсутствие повышения версии, поиск извлечённого APK, скрытый ввод пароля с пробелами и Enter для повторного использования пароля, отказ перезаписывать готовый файл. Хеш исходного тестового хранилища остаётся неизменным. Результат: docs/verification/phone-signing-pkcs12.json. Подпись реальным ключом пользователя и фактическая установка на его телефон выполняются локально; здесь не заявляются.

Для сборки стабильного кандидата: `gradle :app:assembleRelease -PaudiobookChannel=stable`. Встроенные обновления разделяют stable-v и preview-v; неподписанный кандидат не предлагается как готовое обновление. Фоновая уборка сохраняет каталоги с аудиофайлами. Исходная сборка 38 и её Android-проверки остаются без изменений: исправлен только процесс подписи.
