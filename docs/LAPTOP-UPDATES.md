# Обновления с ноутбука

Задача владельца 2026-11-01: собирать APK на ноутбуке и скачивать его с телефона
без Tailscale на телефоне. Для этой задачи явно выбраны обычные проверки без ub-mode.

## Адрес и устройство

Публичный адрес: https://audiobook-laptop.tail1dbbf9.ts.net/ . HTTPS Funnel передаёт
запросы к `127.0.0.1:8787` на ноутбуке DESKTOP-QG19B0C. APK хранится на ноутбуке;
GitHub не участвует в передаче обновления. Интернет-реле предоставляет Tailscale.
На телефоне достаточно браузера. При отключённом ноутбуке адрес недоступен.

Задача Планировщика `Audiobook Update Server` запускает
`scripts/laptop-update-server.py` после входа владельца в Windows. Сервер слушает
только loopback и обслуживает строго разрешённые адреса отдельной папки:
`C:\Users\иван\Documents\Codex\2026-11-01\audiobook\outputs\laptop-updates-public`.
Исходники, ключ подписи, книги и настройки в эту папку не копировать.
Funnel настроен с `--bg`, его конфигурация сохраняется службой Tailscale.

## Первый переход

Версия 4.2.88 содержит адрес прежнего сервера. Поэтому первый APK нового канала
нужно скачать со страницы ноутбука и установить поверх существующей Audiobook.
Не удалять приложение и не очищать данные. После перехода раздел «Обновления»
использует адрес ноутбука. Сам установщик Android требует подтверждения владельца.
Оригинальную стабильную `com.audiobookdownloader` не трогать.

Пакет обновляемого приложения: `com.audiobookdownloader.preview`.
Сертификат SHA-256:
`3a4cecd14bb3e983843871766909c3f07b3dc64379800f3e270e4a27d39affb7`.
Прежний Preview-ключ восстановлен из существующего приватного recovery-артефакта
и хранится вне репозитория и публичной папки в
`%LOCALAPPDATA%\Audiobook\signing\preview.keystore`.
Доступ к файлу ограничен владельцем и SYSTEM. Новый ключ не создавать.

## Следующая локальная сборка

Сначала проверить текущую опубликованную версию и GitHub run number, выбрать
неиспользованный номер строго больше уже установленного/опубликованного.
89 зарезервирован для первой локальной версии. CI-offset увеличен до2, чтобы
следующий raw88 создавал90, а не повторял89. После будущих локальных выпусков
снова согласовать номера; не переиспользовать код с другим APK.

Из PowerShell в репозитории (пример для первой версии):

```powershell
& .\scripts\windows-development.ps1 -GradleArguments @(
  ':app:testReleaseUnitTest', ':app:assembleRelease', ':app:lintRelease',
  '-PaudiobookReleaseNumber=89', '--console=plain', '--no-daemon',
  '-Dorg.gradle.jvmargs=-Xmx2304m -Dfile.encoding=UTF-8', '--max-workers=2'
)
```

Скрипт подхватывает установленный SDK/Java и существующий приватный ключ.
Для совместимости Java17/Gradle с кириллицей в профиле используются NTFS-junction
`%PUBLIC%\Documents\AudiobookDev\AudioBook` и `gradle-cache`. Они ведут к исходному
репозиторию и прежнему кэшу; файлы не перемещаются и второй клон не создаётся.
Gradle запускается из этого пути, `GRADLE_USER_HOME` задаётся только процессу.
Файл Google `com.android.tools.external.com-intellij:kotlin-compiler:31.7.3`
потребовал отдельной докачки; его официальный SHA1
`c45cdfa841c3f0faf60296689df38e870471c1b4` проверен перед помещением в локальный кэш.
Preview по умолчанию использует ноутбук, стабильный неподписанный кандидат
сохраняет прежний origin. Переопределение возможно свойством
`-PaudiobookUpdateOrigin=https://host`, только HTTPS без пути/учётных данных.

После успешных проверок запустить `scripts/publish-laptop-update.py` с аргументами
`--apk`, `--directory`, `--build-tools`, `--release-number`.
Публикатор проверяет пакет, версию, подпись, отсутствие отладки, разрешения,
DEX и встроенный origin. Он копирует APK в версионный каталог, затем атомарно
обновляет manifest и страницу. Версионные адреса в `parts` не меняются при
публикации следующего выпуска; SHA и подпись дополнительно проверяет приложение.
Нельзя заменять APK уже опубликованного номера.

Для полного цикла проверок, сборки и публикации есть одна команда:
`& .\scripts\build-laptop-update.ps1 -ReleaseNumber 89`.
Её выполнять только после выбора свободного номера; при любой ошибке проверок
публикация не запускается. Для следующего выпуска заменить89 новым номером.

Проверки сервера: `python scripts/tests/test-laptop-update-server.py`.
Проверять полный публично скачанный APK по SHA-256. На самом ноутбуке MagicDNS
возвращает приватный IP: для проверки интернет-реле можно получить A-записи
через публичный DNS и использовать `curl --resolve host:443:public-IP` с обычной
проверкой сертификата. Не отключать TLS-проверку.

## Управление

```powershell
Get-ScheduledTask -TaskName 'Audiobook Update Server'
Start-ScheduledTask -TaskName 'Audiobook Update Server'
& 'C:\Program Files\Tailscale\tailscale.exe' funnel status
# Остановить только публикацию обновлений:
& 'C:\Program Files\Tailscale\tailscale.exe' funnel --https=443 off
```

Резерв исходников в `backup/audiobook-laptop` работает отдельно от сервера APK.
Облачная разработка при отключённом ноутбуке описана в REMOTE-DEVELOPMENT.md;
она не делает отключённый ноутбук доступным и не переносит автоматически
этот сервер обновлений в GitHub.
