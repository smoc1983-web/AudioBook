# Восстановление ссылки главы: журнал

2026-11-04. Применяется одобренный пользователем ub-mode. Новый выпуск не публикуется.

1. Изучены PlaybackService, сохранение editionId и book_url, ContinuationHttp.
   Устаревшая ссылка ранее немедленно завершала воспроизведение ошибкой.
2. Созданы проверки неоднозначных глав, перестановки глав, смены файла/хоста,
   небезопасных схем и ошибочных данных. Пустой parser дал ожидаемый отказ
   проверки восстановления. После реализации прошли восемь JUnit-тестов.
3. Ограничено обновление: та же editionId, известная страница книги, единственная
   глава с тем же нормализованным названием, HTTPS и прежние CDN-хост/путь.
   Изменяться могут параметры ссылки; другая запись автоматически не выбирается.
4. Поддержаны встроенные KB/App.playerInit и XSPlayer. Нативный bounded HTTP
   использует правила известных источников, таймауты, лимиты тела и проверку
   перенаправлений. Скрипты не исполняются. Защищённые сеансом страницы и внешние
   плейлисты могут потребовать повторного открытия книги.
5. Сервис делает одну попытку при ошибке/таймауте подготовки. Позиция и намерение
   паузы/пуска берутся после запроса, скорость остаётся настройкой сервиса.
   Смена главы/книги и остановка отменяют задание; generation отклоняет поздний ответ.
6. Сохранённая страница Библуса проверяет обновление реального формата подписанной
   ссылки. Аудио на физическом устройстве и полный поток повторного запуска пока
   не проверены. Это частичная реализация этапа3, не универсальный refresh всех сайтов.
7. JaCoCo: refresh100%, readTracks98.8%, safeAudio92.9%, match94.3%, остальные
   изменённые методы100% до добавления двух граничных проверок. Crapper: CRAP4–9;
   Dryer не нашёл кандидатов >=0.8. Kotlin не покрывается этими анализаторами.
8. Mutator сначала оставил 3/35 выживших: пустое имя главы и неверный URI.
   Добавлены проверки этих границ. Итог35/35 уничтожены, выживших0. Это выбранные
   мутации ChapterRefreshRules, не полный анализ сервиса или парсера.
