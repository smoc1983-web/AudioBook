# Уведомления только по книгам из коллекций

Исправление опубликовано после явного разрешения: [Audiobook4.2.70](RELEASE-4.2.70.md). Ниже журнал разработки и проверки до публикации.

После ручной 4.2.69 пользователь показал уведомления о посторонних новинках Литрес.
Причина: LitresReleaseScanner независимо читал общий каталог новых аудиокниг;
AbContinuationAlerts добавлял искусственный seed «litres» в список допустимых
подписок. У книги не требовалось быть связанной с коллекцией.

## Исправление

- Общий feed scanner и его вызовы удалены. Даже со старым включённым litres_enabled
  пустые коллекции не вызывают запросов к общей ленте и не создают оповещений.
- CollectionNoticePolicy допускает только реальные идентификаторы книг из текущих
  активных коллекций. Выключенные подписки не входят в них. Этот фильтр применяется
  к списку уведомлений, переходам по уведомлению и непосредственно перед отправкой.
- Сохранённая подписка Литрес теперь означает аудиопродолжения подтверждённых прямых
  серий коллекционных книг. Проверяются автор, собственный цикл, формат audio,
  published, явный номер и полная свежая страница. Первая выборка тихая, анонсы,
  спорные/неполные списки не продвигают состояние. Текстовый baseline v2 сохранён.
- После сети повторно проверяется наличие исходной книги в коллекции.
- При запуске и изменении коллекций отменяются посторонние tagged id=1 уведомления
  этой функции. Уведомления плеера и загрузок имеют другие идентификаторы.
- Старые записи общего seed=litres удаляются из inbox. Законная история сохраняет
  read/notified; история книг, убранных из коллекций, скрыта от текущего списка.
- В настройках подписка названа «Продолжения моих серий на Литрес» и поясняет область
  действия. Список обновляется при изменении коллекций, а не на каждом изменении
  посторонних настроек плеера.

## Проверка и журнал

1. Извлечена прежняя проверка права на уведомление без изменения её поведения:
   два регрессионных случая из четырёх воспроизвели допуск общего Litres seed.
2. Убрано исключение для общего провайдера. Локальный JVM-прогон: 111 тестов без
   ошибок, один необязательный live-сценарий пропущен.
3. Свежий JaCoCo/Crapper нового Java-предиката: CRAP 1.0; Dryer активных Java-классов
   не нашёл кандидатов >=0.8. Mutator не сгенерировал sites для одного вызова метода:
   N/A, а не успешный mutation gate. Kotlin этими версиями инструментов не покрывается.
4. Android-регрессии используют настоящий NotificationManager: посторонние записи
   отменяются, нужная отправляется и помечается notified, сообщение плеера остаётся.
   Удаление коллекции прекращает показ, старый посторонний intent не открывается.
5. Reference-fixtures проверяют аудио Литрес только для текущей прямой серии,
   тихую первую сверку, повторную проверку, неполный список и удаление во время сети.
   Существующие тесты аудиоисточников и текстовых продолжений остаются.
6. Первый Android36 прогон: 11 случаев, проверка уведомлений прошла; один прежний
   cold-search тест обнаружил кеш из другого случая. Изоляция тестовых кешей
   исправлена с восстановлением прежних значений, исходные assertions сохранены.
7. Рабочая ветка fix/collection-notices-only. Основная ветка, APK для телефона 4.2.69
   и feed100068 не меняются. Новая публикация требует отдельного разрешения.

Итоговый [CI40550108807](https://github.com/smoc1983-web/AudioBook/actions/runs/40550108807)
прошёл: Android23 и Android36 по11/11 без пропусков и ошибок; Debug JVM по127
(один необязательный live-пропуск). Сохранены настоящие native XML и хеши архивов.
Источник приложения2475a54, проверочный cache-isolation commit c6a0104.

Результаты, ограничения и CI: [collection-notifications/verification.json](collection-notifications/verification.json).
Библиотека, коллекции и ключи подписи не очищаются и не меняются.
