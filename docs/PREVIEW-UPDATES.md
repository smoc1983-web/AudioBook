# Audiobook Preview: параллельная установка и обновления

Стабильная Audiobook остаётся `com.audiobookdownloader`. Новая сборка имеет пакет
`com.audiobookdownloader.preview`, название Audiobook Preview и ярлык с полумесяцем, Play и книгой.
Первую Preview устанавливают один раз; удалять стабильную версию не нужно.

С 25 октября 2026 по решению владельца именно Preview является основным каналом дальнейшей разработки и обновлений. Параллельное подключение старых скачанных книг — [PREVIEW-AS-MAIN.md](PREVIEW-AS-MAIN.md).

Preview использует собственные настройки, историю, виджеты, сервис, уведомления,
провайдеры файлов и папку `Download/AudioBooks-Preview`. Она не переносит и не
очищает папку стабильной версии `Download/AudioBooks`. Ранее скачанные книги
остаются в стабильном приложении; библиотека Preview изначально отдельная.
Разрешение Android на чтение аудио общее по типу, но автоматический поиск ограничен
папкой Preview. Пользовательский выбор другой папки через системный диалог явный;
файлы из выбранной папки могут удаляться только по действию пользователя.

## Обновление на телефоне — начиная со сборки 48

1. Настройки → Обновления Audiobook / Audiobook Preview.
2. «Проверить обновления» → «Загрузить обновление».
3. После проверки файла — «Установить загруженное обновление». Android при необходимости попросит разрешить установку из приложения, затем подтвердить обновление.

В окне ровно три кнопки; поля аккаунта, создание GitHub-ключа, сохранение подключения и отключение GitHub удалены. Канал файлов публичный, исходники и ключи остаются закрытыми. Подробности и формат частей APK — [PREDANIE-AND-DIRECT-UPDATES.md](PREDANIE-AND-DIRECT-UPDATES.md).

Автопроверка при запуске выполняется не чаще раза в сутки и сохраняет прежнее значение настройки auto, если оно уже было задано. Сетевые ошибки проверки не мешают воспроизведению. Загрузка идёт в открытом окне обновлений; закрытие окна отменяет её. Проверенный APK можно установить позднее.

Проверяются размеры и SHA-256 каждой части и целого APK, пакет, строго более высокий versionCode и совпадение сертификата с установленным приложением. Последнюю проверку и согласие на установку выполняет Android. Установленную стабильную Audiobook не удалять. Для обновления именно старого пакета com.audiobookdownloader нужен исходный телефонный ключ; это ограничение не относится к принятому режиму отдельной Preview. stable-feed не содержит unsigned кандидатов. Следующие выпуски устанавливаются поверх Preview с её прежней подписью через preview-update.json.

## Сборка и подпись; прежний закрытый канал до сборки 48

Workflow `build-apk.yml` автоматически запускает тесты и собирает Preview после push
в main. Ручной workflow_dispatch допускает сборку рабочей ветки без публикации.
GitHub release по-прежнему хранит артефакты сборки из main для владельца. Старые версии до 48 читают этот закрытый канал; новые используют отдельный публичный read-only feed. После CI проверенный подписанный APK публикуется в нём через tools/package-public-update.py и Sites. Обновления публикуются только из main. VersionCode равен
100000 + GITHUB_RUN_NUMBER; имя — 4.2-preview.<номер>. После проверки APK workflow
публикует **закрытый prerelease** `preview-v<versionCode>` с двумя файлами:
`Audiobook-Preview.apk` и `preview-update.json`. Исходники не становятся публичными.
Публикация завершена только после загрузки обоих файлов; незавершённый draft
обновлятор игнорирует. Музыкальный репозиторий ForTanya не изменяется.

Preview подписывается своим RSA-ключом, не связанным с неизвестным ключом стабильной
версии. Ключ хранится в закрытом Actions cache; резервная копия — отдельный
**приватный** artifact `preview-signing-recovery`, срок хранения 90 дней.
В APK и release этот artifact не входит. При пропаже cache workflow пытается
восстановить ключ из artifact. Если канал уже опубликован, а ключ утерян, сборка
завершается ошибкой и не заменяет подпись установленным пользователям.
Публикация дополнительно сверяет сертификат с предыдущим manifest.

**Для постоянного хранения владельцу нужно один раз скачать приватный artifact
`preview-signing-recovery`, сохранить файл вне Git и создать repository secret
`AUDIOBOOK_PREVIEW_KEYSTORE_BASE64`**: base64 файла `preview.keystore` без переносов.
Alias `audiobook-preview`, store/key password `android` (ключ исключительно Preview).
Это снимает зависимость от сроков хранения cache/artifact. Не загружайте ключ в Git,
публичные release или приложение; доступ к artifact оставляйте только доверенным
сотрудникам. Пока secret не создан, первый и последующие запуски работают через
cache/recovery, с остановкой при невозможности безопасного восстановления.

## Проверка

CI: source unit tests, live catalogue/audio decoding tests, Preview policy tests,
сборка APK, `aapt` проверка package/version, `apksigner verify`, checksum manifest.
Тесты обновлятора проверяют отказ для стабильного/музыкального пакета, одинаковой
или старой версии, неверного размера/hash, путей вне разрешённых адресов и запрет
передачи GitHub-ключа на CDN. Установка, возврат из системных настроек разрешения
и воспроизведение двух приложений требуют проверки на реальном телефоне.

Локальная сборка без PREVIEW_KEYSTORE использует стандартный Android debug-ключ.
Для установки поверх Preview из GitHub укажите PREVIEW_KEYSTORE на сохранённый
ключ Preview; иначе обновлятор правильно откажет из-за другой подписи.

При ошибке главного экрана исправленная Preview показывает нативные кнопки
«Диагностика и отчёт TXT» и «Обновления Preview». Для этих действий не требуется
работающий Compose-экран. Отчёт открывается только по нажатию пользователя.
Публикация новых APK также требует успешного инструментального теста Android 36.
