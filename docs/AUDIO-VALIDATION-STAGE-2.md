## Результат

Успешный ответ DownloadManager означает окончание передачи, после которого
следует отдельное состояние **«Проверка файла»**, затем `complete` либо `error`.
Это применяется к долговременной очереди и восстановлению старых Android-заданий.
Новые непроверенные или отклонённые файлы исключаются из библиотеки и резервной
копии; отказ проверки виден в окне загрузок. Отклонённый файл не удаляется сразу.

Проверка выполняется в IO по локальному дескриптору DownloadManager:

* файл открывается на чтение, проверяется ненулевой фактический размер;
* размер сравнивается с известным размером передачи DownloadManager, включая
  сохранённое ранее значение; отрицательный/нулевой ожидаемый размер не выдумывается;
* анализируются первые 16 КиБ: HTML/XML-ошибки и HLS/DASH-плейлисты получают
  отдельные сообщения; для RIFF/WAV проверяется граница объявленного контейнера;
* Android MediaExtractor определяет фактическую аудиодорожку/MIME и читает первые
  аудиопакеты. Расширение и присланный HTTP Content-Type не считаются доказательством;
* проверяется чтение последних 4 КиБ файла и неизменность файловых метаданных
  во время проверки. Целая книга не загружается в оперативную память.

Синтетические fixtures содержат MP3, AAC/ADTS, MP4-аудио (M4A/M4B), WAV, FLAC,
Ogg/Vorbis и Opus; проверяются с необычным расширением `.unusual`.
В production APK тестовые аудиофайлы не входят. Их общий размер — 151143 байта.

## Повтор и сохранность данных

При явном повторе или отмене отклонённой загрузки удаляется только собственное неуспешное HTTP-задание или
задание, файл которого был отклонён проверкой. Для отклонённого файла сверяются
владелец назначения, URL/название задания Android и неизменность метаданных файла.
Прежние проверенные главы не скачиваются повторно и не удаляются.

Для старого задания без записи владельца требуется точное совпадение URL,
названия и канонического пути назначения приложения; иначе повтор завершается
понятной ошибкой с сохранением файла. Изменённый после отказа файл проверяется
заново. Отметка старого отказа сама по себе не разрешает его удаление.

`verifying` сохраняется в прежней JSON-очереди и распознаётся после восстановления.
Очистка завершённых записей сохраняет ожидающие задания без Android ID.
Остановка очереди сохраняет уже полученные файлы; законченная передача должна
пройти проверку, прежде чем стать готовой главой. Копирование в резервную копию
при проверке запрещено так же, как при незавершённой загрузке.

Пакет, версия, сертификат, ID книг/глав, аудиофайлы других заданий, позиции,
закладки и коллекции не менялись. Updater и его проверки SHA-256/подписи не менялись.

## Ограничения

Это проверка пригодности полученного аудиофайла, а не полное декодирование всех
глав. Без доверенной контрольной суммы или достоверного ожидаемого размера
нельзя гарантировать обнаружение повреждения в середине или любого обрыва потока.
Файловые метаданные используются для защиты повтора от замены файла; это не SHA-256.

Ранее скачанные книги без живого задания Android массово не перепроверяются и
не удаляются. Полная проверка существующей библиотеки относится к будущему этапу.
Фоновое восстановление по-прежнему зависит от ограничений WorkManager/Android;
переделка хранения и восстановления очереди относится к этапу3.

Локально Android SDK/Gradle отсутствуют; Android-проверки выполняются в GitHub
Actions. Stable APK собирается без подписи, Preview для эмулятора — только с прежним
ключом. Физическое устройство, старые версии Android и все реальные CDN этим
этапом не проверены. Новый релиз не опубликован. Этап3 без подтверждения не начинать.
