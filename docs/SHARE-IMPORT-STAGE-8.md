# Этап 8: импорт аудиокниг через «Поделиться»

Рабочая ветка: `cloud/share-import-20261117`, база `3c37db9`.
Пакет, версия, сертификат подписи и публичная 4.2.95 не меняются. Публикация не разрешена.
Это один пакет этапа 8; несколько корней библиотеки, редактор метаданных,
загрузка следующего тома по Wi-Fi и новые фильтры ещё не реализованы.

## Поведение

Из файлового менеджера: «Поделиться» → Audiobook либо «Открыть с помощью» для
поддерживаемого audio MIME. В библиотеке есть «Импортировать файлы» с системным
выбором нескольких документов. При недоступном URI доступен повторный выбор
сохранённой копии. Закрытый кэш Telegram не открывается по обычному пути.

До импорта пользователь подтверждает название и порядок. Изначально применяется
естественный порядок чисел (1,2,10), затем главы можно переставить. Каждый файл
становится одной главой; исходное имя показано в подтверждении и сохранено в
манифесте, внутренние имена глав числовые. Звук автоматически не запускается.
Применяются выбранные тема и масштаб текста; остальные экраны не переделывались.

Приложение копирует данные в свою внутреннюю папку. Оригиналы не изменяются и не
удаляются. При удалении приложения внутренняя копия пропадёт; для переноса есть
существующий экспорт библиотеки. Это импорт файлов, не сканирование папок,
не загрузка URL, не импорт ZIP/текста и не постоянное подключение облака.

## Сохранность и проверки

- Только bounded `content://` URI с правом чтения. `file://`, HTTP(S), собственные
  приватные провайдеры, некорректные/слишком многочисленные вложения отклоняются.
  Новых разрешений хранения и сетевых запросов нет.
- До 128 файлов, 2 ГиБ на файл, 8 ГиБ на книгу. Неизвестный размер допустим;
  известный проверяется по реально прочитанным байтам. Копирование потоковое.
- Применяется существующая проверка `AbDownloadedAudio`: префикс/хвост,
  MediaExtractor, наличие и чтение аудиопакетов. HTML/пустые/неполные файлы не
  публикуются. Суффикс выбирается по контейнеру/аудио MIME; необычное исходное
  расширение не означает повреждение. Это структурная проверка, не полная
  расшифровка/прослушивание всей книги; DRM/неподдерживаемые форматы не обещаны.
- Временная папка публикуется одним rename после проверки всех глав и записи
  манифеста с fsync. Отмена до публикации очищает только собственный staging;
  оставшийся после остановки процесса staging убирается при следующем импорте.
  Финальная публикация — точка фиксации: поздняя отмена уже опубликованную книгу
  не удаляет. Импорт не возобновляется автоматически после уничтожения процесса.
- SHA-256 упорядоченных байтов глав определяет editionId; канонические имена глав
  сохраняют chapterId при повторной передаче из другого URI/под другим именем.
  Это локальная идентификация/контроль повторной копии, не подтверждение автора
  или безопасности внешнего файла. Порядок/состав изменён — другое издание.
- Повторный импорт проверяет существующие файлы и не создаёт дубль. Отсутствующие
  главы восстанавливаются отдельно, изменённая существующая глава не затирается.
  Правильные файлы, закладки и позиция остаются; другое содержимое с прежним
  названием получает отдельное название. Зарезервированные старой позицией,
  очередью/коллекцией названия не присваиваются чужому изданию.
- Новые записи используют существующие EditionMetadata/StableProgress/backup.
  Если фиксация файлов пережила запись preferences, сканирование восстанавливает
  отсутствующий каталог/маркер по проверенному манифесту. Повреждённые прежние
  метаданные не переписываются; о неудачной регистрации сообщается отдельно.
- Удаление через существующее меню удаляет собственные копии и только известные
  sidecar-файлы импорта; провайдер источника для удаления не вызывается.
- При копировании pipe проверяется отмена каждые 250 мс, отсутствие данных — до
  30 с. Android-провайдер, застрявший внутри Binder/open/query и игнорирующий
  CancellationSignal, может задержать освобождение фоновой операции; UI отмены
  не ждёт его. Жёсткого срока для произвольного стороннего провайдера нет.

## Изменённые компоненты

`AbDownloadedAudio.kt`: исправлен конец потока после `advance()` на API23;
первый аудиопакет, размер и контейнер проверяются по-прежнему.
`SharedAudioRules.java`: URI/границы, порядок, имена/контентная идентичность/форматы.
`SharedAudioImport.kt`: разбор Intent, описание, отмена, staging, проверка, дедупликация,
восстановление и реестр приватных книг.
`SharedAudioImportActivity.kt`: отдельный приёмник/retained ViewModel/подтверждение.
`AndroidManifest.xml`: SEND/SEND_MULTIPLE/VIEW audio-файлов.
`current/MainActivity.kt`: вход импорта, scanner/deletion integration, library route;
`AbGlassWidgets.kt`: route в библиотеку, прежние widget intents сохранены.
Тесты: `SharedAudioRulesTest`, `SharedAudioManifestTest`, `SharedAudioImportTest`,
`SharedAudioPanelTest` и отдельный тестовый provider/sender APK.
CI: `.github/workflows/share-import.yml`, `docs/quality/share-import/native-tests.sh`.
