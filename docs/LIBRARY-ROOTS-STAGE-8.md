## Изменения для пользователя

Библиотека → управление доступом/синхронизацией → «Папки библиотеки».
Можно добавить до32 папок через системный выбор Android, просмотреть их список,
повторно выбрать недоступную папку и отключить отдельное подключение с
подтверждением. Выбор следующей папки не заменяет предыдущую. Дубликат одного
подключения не добавляется; два разрешения на один документ одного провайдера
не удваивают книгу.

Прежняя `library_tree_uri` переносится добавочно в JSON schema1 `library_roots_v1`.
Старое значение не меняется и не удаляется. После явного отключения всех папок
пустой список считается выбранным состоянием, а не причиной заново подключать
старый grant. При первом переходе сохранён прежний fallback: единственное
постоянное read-разрешение на папку с именем LIBRARY_DIRECTORY может восстановить
старую настройку, если ни списка, ни одиночной настройки ещё нет.

Отключение не удаляет аудио, позиции, заметки, коллекции или очередь. Постоянный
URI grant автоматически не отзывается: он может использоваться текущим плеером,
очередью, резервными копиями и другими подключениями. Android/провайдер может
ограничивать число разрешений; освобождение shared grants без доказательства
владения не производится. Стандартная папка Download/LIBRARY_DIRECTORY и копии
Share по-прежнему обнаруживаются отдельно; их книги могут оставаться видимыми
после отключения соответствующего дополнительного подключения.

Место новых скачиваний не меняется, файлы не копируются и не перемещаются.
Обход сохраняет прежнюю глубину: выбранная папка и непосредственные папки книг.
Рекурсивное индексирование всей карты памяти/сети не добавлялось.

## Стабильность и идентичность

- Вход — ограниченный по длине content tree URI, без HTTP/file, query/fragment/userinfo/port.
  Документный ID непрозрачен: не используется как произвольный файловый путь.
  Read-only постоянное разрешение достаточно; write не обязателен. Проверка
  `persistedUriPermissions` выполняется до фиксации подключения.
- Ошибка отдельной папки/подпапки отражается у соответствующего подключения;
  успешно прочитанные остальные папки остаются в результате. Недоступное
  подключение не удаляется из настроек, позиция/закладки не обнуляются.
- Для наложенных tree grants идентичность по authority + documentId. Виртуальный
  File-путь строится по SHA256, а не32-битному hashCode: разные `Aa`/`BB` не
  объединяются случайно. Реальные папки/файлы не переименовываются.
- Первая наблюдённая URI документа записывается отдельно от текущей URI доступа
  в device-local `audiobook_library_origins_v1`. `LibraryBook.identityOrigin`
  сохраняет прежний bookId и ambiguous-edition derivation, если сменился только
  grant root; чтение/удаление использует актуальную разрешённую URI. Форматы
  chapterId/checkpoint/закладок не меняются.
- Одноимённые папки без доказанного издания по-прежнему защищаются прежней
  ambiguous-логикой. Новая функция не угадывает соответствие по названию и не
  решает полностью прежнюю title-зависимость BookRef/списков. Отдельная миграция
  модели/редактор метаданных потребуется для удобного выбора таких изданий.
- Фильтр незавершённых/отвергнутых загрузок действует только в папке скачиваний
  Audiobook, включая её канонические алиасы. Одноимённый внешний аудиофайл не
  скрывается из-за чужого задания. Недопроверенная собственная глава по-прежнему
  скрыта; приватный symlink-тест проверяет обход через файловый алиас.
- Origins записываются одной пачкой за сканирование, только для новых книг.
  Конкурирующие сканы используют один first-writer; исходная повреждённая запись
  не затирается. Неуспешная запись не выдаётся за устойчивую только потому, что
  SharedPreferences уже изменил RAM: pending + write nonce позволяют повтор;
  новые неподтверждённые origins до успешной записи не публикуются.
- Повреждённый список не заменяется пустым. Добавление/удаление блокируется,
  предлагается явное восстановление с сохранением точного raw/type в отдельный
  private snapshot и возвратом старой одиночной папки. Первый снимок не
  перезаписывается при повторной порче; повторный отказ требует анализа/экспорта
  сохранённой записи, а не скрытой очистки.
- Неудачный commit списка сохраняет прежние подтверждённые корни для чтения;
  сообщение об ошибке не зависит от оптимистичного RAM-значения preferences.
- Новые настройки/URI grants/origin-map не входят в backup allowlist и облачный
  progress exchange. На другом устройстве доступ нужно выдать заново. В trace
  добавлены только количества папок/отказов, без URI/имён каталогов.

## Компоненты

- `LibraryRootRules.java`: URI/doc identity, идемпотентное добавление,32-root limit.
- `LibraryRoots.kt`: миграция, сохранение/отключение/подтверждённое восстановление,
  постоянные read grants, сериализация origins с first-writer и batch commit.

- `LibraryRootsPanel.kt`: список/состояния, выбор Android, подтверждения в текущей

  списка, стабильный identityOrigin и per-root issues; основной UI не переделан.
- `EditionMetadata.kt`: ambiguous identity следует прежнему origin документа.
- Тесты `LibraryRootRulesTest`, `LibraryRootsCodecTest`, `LibraryRootsTest`,
  `LibraryRootsPanelTest`; отдельный test APK DocumentsProvider и sender/grants.
  Старые LocalContinuationPlayback fixtures теперь явно устанавливают/возвращают
  authoritative список, а не меняют только legacy key после миграции.

## Что не проверено

Физический телефон/картаSD/USB/реальные облачные провайдеры, процесс kill/reboot,
заполнение диска и Installer не проверялись. Отказы commit в тестах моделируются,
а не выдаются за настоящий disk-full. Произвольный DocumentsProvider может
застрять в синхронном query/Binder: жёсткого deadline/параллельного обхода нет;
такой provider способен задержать сканирование, хотя хранение/плеер отдельные.
Перемещение/переименование, при котором provider выдаёт новый documentId, не
сопоставляется автоматически с прежней книгой. Origin-map локален устройству.
Весь исторический native-набор не запускается: выбираются относящиеся к изменению
и прежним критическим функциям regression classes/methods. Батарея/RAM не измерялись.
Этап8 в целом не завершён: дальше редактор метаданных, согласованная загрузка
следующего тома по Wi-Fi и дополнительные фильтры поиска.

использовании ещё не закрытого окна-отправителя. Добавлены подтверждение окончания
действия через ResultReceiver/onDestroy и отдельная disposable task. Здоровая
вторая папка дополнительно проверяется открытием реальных байтов через resolver.
